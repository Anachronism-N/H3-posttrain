# ChoreoBench 验收与开发诊断记录

记录范围：2026-11-04 的初始 CPU 验收、2026-11-05 的 Linux 集群真实模型开发诊断，以及第11节同日缺陷修复后的Windows软件回归。

**结论边界：软件与真实推理流程已验收；没有正式数据集、人工音乐适配结论、排行榜或方法领先结论。** 后续参数/提示多次根据同三首开发歌曲调整，因此这里不是冻结测试集结果，不能称为 SOTA 或独立科学验证。运行原始证据在实验存储中保留，不随代码推送音频、模型权重、调用日志或私有评审答案。

## 1. 三类证据必须分开

| 证据 | 已验证 | 不能推出 |
|---|---|---|
| CPU fixture / mock | 数据流、时钟、schema、预算、恢复、来源与权限合同 | 音乐理解、编舞质量或真实模型可运行 |
| 真实 GPU / 文本服务 | 指定模型配置下的加载、生成、EOS、格式、成本与失败 | 普适容量保证、音乐性、动作可执行性或长期服务可靠性 |
| 独立盲评 | 包和页面已生成，真实音频与计划可查看 | 尚未收到完成评分；所有质量结论保持 pending |

核心评估只给格式、排程、覆盖、字面目标与保护诊断。语义、音乐、人体物理和偏好不由程序自动计分。

## 2. CPU 验收历史与最终结果

### 初始开发机

Windows / Python 3.9.18，NumPy 1.26.4、SciPy 1.13.1、soundfile 0.13.1；没有 torch、Transformers、真实权重或付费 API。

| 阶段 | 完整 ChoreoBench 测试 |
|---|---:|
| benchmark 与参考 baseline | 154 passed |
| 候选复用、编辑与评估加强 | 286 passed |
| 规划块、选择 harness、常驻原生服务 | 420 passed |

180 秒合成音频端到端检查：36 窗、K=2、72 次 mock 局部调用；人工声明 reviewed 的计量 fixture 产生 24 个规划单元，strict 编译覆盖约 0.995486。候选库跨 concat/global/hierarchical 复用不新增局部调用。以上全部为软件流程证据。

初始远端 Windows/Python 3.12 暴露 path stat 与 handle fstat 的 ctime 语义差异；修复后使用相同 API 的前后句柄比较，并保留修改/替换检测。远端 CI 状态以对应提交的 GitHub Actions 为准，不从本地测试推断。

### Linux 最终回归

- Python 3.11.6；复用已有音乐环境的音频依赖。
- 协调迭代结束时487 passed；发布前补充公开音频path stat/handle fstat跨平台语义回归后：**488 passed，148 subtests passed**。

- 新公开网页 HTTP 专项：初次17 passed，发布前新增时间戳语义回归后18 passed；真实 Chromium 验收另列。
- Git whitespace 和新增模块语法检查通过。
- 较早默认环境的 427 passed + 1 skipped 中，跳过原因是缺 soundfile；补齐已有音频环境后重新执行，不把当时跳过项冒称通过。

以上数字对应本次实现版本；新增/改变版本应重新验收。原有 H3/5 秒训练 adapter 源码及输入合同未修改。

## 3. 模型、输入与来源

### 局部模型

没有已训练音乐到编舞 Qwen checkpoint，本轮使用 **原始 Qwen3-Omni-30B-A3B-Instruct Thinker + 固定公开任务提示**：

- 单设备完整 BF16 Thinker，不加载 LoRA、不执行 Talker/code2wav、不自动量化或分片。
- 每次听完整 5.0625 秒音频；16kHz 下为 81,000 样本。
- 一次回答要求两段文本：[0,2) 与 [2,5.0625)。这是兼容原局部协议的提示选择，不是模型能力限制或检测到的动作边界。
- 原始回答、实际格式化模板、seed、token/EOS、模型/processor/源码哈希保留。
- 不向局部模型传全曲计划、前段历史、编辑指令、私有目标或参考编舞。

首窗真实环境为 torch 2.8.0+cu129、Transformers 5.18.0，GPU A800-SXM4-80GB、driver 580.105.08。模型/processor/checkpoint（本轮无 checkpoint）身份以原证据包为准，不以目录名担保。

### 外层模型

先试普通 Qwen3-32B，后使用已有 **Qwen3-VL-32B-Instruct 的纯文本模式**，image/video 限额为 0；没有输入图像、视频或音频。BF16、同节点 TP=2，部署 65,536 上下文；原配置上限 262,144，没有做 RoPE 扩展。两个副本使用相同本地权重/tokenizer、dtype 和服务参数。

### 三首真实完整音频

从官方 FMA full archive 按有界 HTTP206 仅获取三首许可记录为 CC-BY 的完整录音，不下载整个约 879GiB archive。保存逐曲许可/归属、ZIP member CRC、音频 SHA 与解码/下混/重采样/必要增益/PCM16 回执。

| 开发歌曲 | canonical 时长 | 5.0625 秒观察窗 | K=2 局部调用 |
|---|---:|---:|---:|
| fma-1881 | 252.9698125 秒 | 50 | 100 |
| fma-3855 | 230.0343125 秒 | 46 | 92 |
| fma-4151 | 217.2081875 秒 | 43 | 86 |

没有裁切整曲、填零、循环或拼接短片冒充整曲。ZIP CRC 和本地 SHA 不等于验证整个 archive 的发布哈希。分组状态 unverified、近重复分组未审，**不具备正式发布资格**；三首全部仅用于开发诊断，未构造正式 train/dev/test。

## 4. 真实局部可运行性

首个完整真实短窗：

| 项目 | 实测 |
|---|---:|
| input / output tokens | 212 / 120 |
| 停止与格式 | genuine EOS，严格双窗通过 |
| 加载时延 | 42.3576 秒 |
| 生成时延 | 9.3238 秒 |
| 峰值 CUDA allocated | 63,578,429,952 bytes |
| 峰值 CUDA reserved | 63,772,295,168 bytes，约 59.39 GiB |
| 加载期主机峰值 RSS | 120,137,420,800 bytes，约 111.89 GiB |

这是一条 batch1、输出预算 512 的验收，不是长期容量或吞吐保证。

三个真实短窗另采 K=2，共 6 次，3/3 concat 计划合法。三首整曲局部共 **278 次调用全部 EOS**，实际输出 33,806 tokens；记录的平均单次生成时延约 7.18 / 7.25 / 8.41 秒。调用时延和约 2,107.65 秒不含加载、哈希、排队、I/O、音乐分析和外层生成，不能当端到端墙钟或完整 GPU 小时。

## 5. 原 baseline 与退化诊断

以下为原始全曲 unknown 结构条件，没有把后来算出的拍点/谱变化偷偷插入已有候选合同。

| 路径 | 合法计划/原歌曲分母 | 诊断 |
|---|---:|---|
| concat | 3/3 | 固定候选0；覆盖 1.0，但窗口边界不是动作真值 |
| global，明确 root 提示 | 3/3 | 正文与时间/轨道序列均逐字等同 concat，未体现全曲组织收益 |
| hierarchical，明确 root 提示 | 2/3 | 一首 outline 截断失败；有效两首仍复制正文，只新增声明 motif |
| index0 strict | 3/3 | 省略不完整来源片段，覆盖约 0.988507 / 0.999036 / 0.988107 |
| llm select-only strict | 3/3 | 新增 25 / 23 / 22 次选择，不允许创造新动作或改变名义时间 |
| 同文本模型完整 no-audio | 2/3 | 一首身体轨道冲突；只给匿名 ID、统一 brief 与总时钟 |

llm 选择器分别在 40/50、38/46、37/43 个窗口取候选1；文字变化不等于整曲编排变化或更优。三个同 seed 真音频短窗产生不同文字，只能说明输入敏感性，未做近 BPM/风格配对，也不证明音乐贴合。

受约束整曲编辑单次改允许事件 action：字面目标/保护通过，原计划 hash 绑定，私有目标不入 prompt，撤销精确恢复；语义/衔接仍 pending。

## 6. 优化迭代与失败账册

不同配置独立输出，旧失败、已提交前缀、源码快照、原始响应和调用成本全部保留；没有静默清洗、unwrap、重排或补采。

| 迭代 | 改动 | 实际观察与边界 |
|---|---|---|
| 基座提示适配 | 原始 Omni 附固定双窗任务 | 真实局部 EOS/格式通过，不称已训练专家 |
| 外层完整 root / patch | 明确字段与对象/数组类型 | 旧 wrapper、operations-only、provenance-array 输出被拒绝，修订另建配置 |
| 长上下文 | 普通32B转 VL32B 纯文本 | 40,960 上下文 HTTP400 保留；旧 global 输入 39,267 + 输出预算16,384 = 55,651，在64K服务内 |
| coordinated v1 | 大纲 + 逐块创作 + 已提交历史 | 主题越段、块时间越界导致失败，不把合法前缀当完整歌曲 |
| coordinated v2 | 当前段主题定义/记忆收紧 | 一个确定软件版本漂移错误单列；旧进程 config 与新 lazy 模块混用，不当作模型质量失败 |
| structured v3 | 动态 JSONschema | 首个后端不支持 uniqueItems 的 HTTP400 保留；控制器继续唯一性验收，独立新schema单块通过；整曲3/3合法 |
| compact v4 | 每块最多3事件，块token2048→1024 | 两项预算一起改变，不称单变量质量消融；三首3/3，但发现0.05秒等工程残块 |
| minblock v5 | 同段短尾合并/容量内平衡 | 不移动公共结构或原观察窗；三首3/3，仍允许真实待审的生成动作和时间缺口 |

谱变化公共结构真实消费 canonical 音频和既有 Beat This，三首得到 8/7/6 个分段，功能标签仍 unknown、repeat_group=null、计量仍 unverified。阈值未校准，不是 All-In-One 或真正乐句检测；只是明确标记的额外公共证据。独立 sidecar 绑定原 dataset bytes/音频时钟，原候选严格身份不放宽。

## 7. 最后 v5 真实结果

配置：同局部候选、同公开结构、同文本模型；每块最多 3 事件、块输出 1,024、纲要 4,096 tokens，time fallback 10.125 秒、容量20秒、短尾目标2秒。

| 歌曲 | 规划单位 | 最短单位 | 新事件数 | 平均事件时长 | 时间覆盖 | 新外层调用 |
|---|---:|---:|---:|---:|---:|---:|
| fma-1881 | 27 | 3.8 秒 | 78 | 3.1394 秒 | 0.968000 | 28 |
| fma-3855 | 26 | 2.285 秒 | 74 | 2.9252 秒 | 0.940998 | 27 |
| fma-4151 | 23 | 4.56 秒 | 66 | 3.2910 秒 | 1.0 | 24 |

全部 schema/整数范围/顺序/主题/引用检查通过，没有未知 API 结果，音频模型新增调用0。新正文不再逐字等同旧拼接，unknown 状态对象均保持为空。

**这不是质量判优表。** 仍有8条低于1秒的生成事件，包括最短0.0725秒；“消除过短规划单位”不等于“消除过短动作”。这些是字面时长审查提示，不是校准的物理指标。覆盖低于1的缺口不自动填休止。主题ID/count、事件减少、正文不同都不能证明动作连贯、音乐理解或可执行性。

## 8. 网页、隔离与资源

最后新盲评包6条，三case每首两个匿名方案（同公共结构 index0 vs coordinated）。旧17条 baseline/编辑/no-audio包和中间页面保留。

- 音频启动哈希及请求身份使用同一fstat API比较，不混用Windows下可能不同的path stat/handle ctime；文件变更拒绝与该差异不误报有独立回归。
- 真实 Chromium 验证 case 锚点、并排计划、单曲统一音频、120秒 seek、两侧活跃动作定位、字段切换保留、6行 JSON 导出、无 JS 错误。
- 测试评分只在浏览器验证后丢弃，不提交/导入；实际评分全部 null，audio_seen=false。
- 白名单 HTTP 服务拒绝私有答案、方法绑定、任意文件/目录和路径穿越；真实音频哈希检查通过。HTTP200不能替代浏览器/质量验收。
- 一个页面构建脚本复制时被截断造成 JS 失败，修复完整短行脚本后重新浏览器验收；原公开pack和空评分JSON未覆盖。
- launcher 本机和代理相对路径已验收；CLI到用户侧网关连接曾超时，不能称独立完成认证访问验收。内网地址和私有部署详情不写入公共仓库，管理员按 VSCODE_PROXY_URI 定位。
- 优化阶段最多单节点4卡、两组 TP=2 文本副本；不重启原 Omni、不终止其他节点任务。结束后全部模型停，节点8卡实际每卡唯一holder约975MiB。网页仅CPU。
