## 五类主图的本轮修改

1. **Overview，两种叙事。** 方法版展开 Qwen3-Omni + LoRA、关节相关从句权重、只读证据缓存、composer/controller/tools 闭环、持久状态、定向修订及分层总谱；评价在生成闭环外。数据版突出当前 2D 事件重写、配对资源和证据评测，以紧凑基线介绍我们的方法。JEV 表示现有全局舞种条件模块；局部专家只展示训练后的模型。未加入独立质量 critic 或动作渲染器。
2. **标注流程。** 保留六阶段及第 4/5 阶段展开，重建全身、手掌与腿部细节，分清重复事件合并与证据保留，音频旁路保留而不进入文本 refiner。这是几何扩展/组件集成图，不是当前全部标签的生产历史；当前标签来自 2D 规则事件文本重写。
3. **数据审计。** 原有密度、长度和部位频率扩为六个来源明确的面板，补源窗口粒度、风格缺失和 producer 自动标记。保留全部配对记录，不把自动通过率或字段一致性称为动作正确率。
4. **编舞样例。** 使用 0、1、2、3、4、5 秒的等距真实帧与测量波形，按预测小节显示两小节单元及尾部片段；用对应 callout 突出身体指代、幅度/方向及延续状态。说明文字由作者编写，非模型预测、人工 GT 或质量评分；片内延续不充当跨独立窗口的 harness 结果。
5. **评价框架。** 分开本地文字、本地音乐适配与全局编排，统一 Q/M/G 标签；给出独立评分、动作引用和听音证据。M3 改为气质/情绪与身体表达的相容性，稳定片段也可评，不要求存在局部转折。

整体使用近白底、浅色分区、低饱和绿/蓝/紫/金及细线，字体统一为 **Times New Roman**。不使用原图整页贴底；示意姿态和波形不冒充统计结果。

## Q/M/G 与旧记录

| 当前显示 | 定义 | 旧字段关系 |
|---|---|---|
| Q1–Q3 | 动作具体性、身体/空间关系、本地时间组织 | 显示对应旧 D1–D3；冻结字段及数值不改 |
| M1–M2 | 节律相容性、动作动力学 | 对应旧 D4–D5 的评价目标 |
| M3 | 音乐气质与身体表达相容性 | **新定义，不是旧 D6 事件响应的别名** |
| G1–G3 | 跨单元连续性、音乐结构、动机复现与变化 | 对应旧 L1–L3 的全局目标 |

旧 D6 的分数、适用门槛和样本覆盖不能复用为 M3。模糊音频证据可记 Unknown；动作文字空泛不因此记 Unknown。允许同一编舞适配多首歌、半速、保持和有依据的反衬。新协议仍须校准；历史四项质量总分也不能重标成新的 G1–G3。

## 六个审计面板的含义与边界

全部面板使用同一组 **22,352** 条严格配对的原始/改写记录，不按 producer gate 过滤。

| 面板 | 定义 | 不能据此声称 |
|---|---|---|
| a 源事件数 | 源规则描述的非空语句数；每个分箱除以配对记录数 | 不同动作类别数或新动作空间 |
| b 改写长度 | 去掉舞种头的英文正文词数 | 与事件数跨单位比较得到压缩或多样性增益 |
| c 部位频率 | wrist/elbow/knee 事件次数占全部源事件次数 | 每段部位出现率、全身观测覆盖或动作正确性 |
| d 源时间粒度 | 每条 5.0625 秒记录已有规则窗口数 | 音乐小节、乐句或 harness 的 2–4 小节单元 |
| e 风格元数据 | 已有标签计数，unknown 保留 | 独立重标结果或音乐—舞种真值 |
| f 自动与身份审计 | producer gate、配对 ID 和源/划分字段一致性 | 人工语义正确率、事件归因完整率或训练测试无泄漏 |

详细口径和研究参考见 [annotation_audit_definitions.md](source/annotation_audit_definitions.md)。未测量的幻觉率、人审准确率、独立歌曲数、歌曲级跨划分重复及真实音画同步，不填成 0 或满分。

## 导出一致性与论文结构

本轮以同一原生 Artifact Tool presentation 为导出主稿：逐图 PDF 来自相同 slide；论文 PNG 是该 slide 渲染结果的精确裁剪。8 项记录均写入 `paper_ppt_consistency.json`，包含裁剪坐标及哈希。修改 PPT 或 SVG 后需要重新导出并更新审计，不能只改论文侧的图片。

已做原生对象、包结构、字体声明和导出一致性检查；**未声称在桌面 Microsoft PowerPoint 中实际打开测试，也未验证其原生字体渲染**。外部编辑器应安装 Times New Roman，渲染差异仍需检查。

论文继续保持拆分结构：`main.pdf` 为 8 页正文加 1 页参考文献，`appendix.pdf` 为独立 8 页附录。本轮图稿交付不把附录重新合入正文。

## 重建方式

编辑对应 SVG 或 `source/build_*.py` 后，依次运行：

```sh
python source/svg_to_native_scene.py
node source/build_native_pptx.mjs
python source/export_paper_from_ppt_master.py
node source/finalize_native_pptx.mjs
```

Python 需要 lxml、fontTools、Pillow 和 PyMuPDF。Node 使用本机捆绑的 `@oai/artifact-tool`；其他环境需设置 `ARTIFACT_NODE_MODULES`，并把 `FIGURE_FONT_DIR` 指向包含 `times.ttf`、`timesbd.ttf`、`timesi.ttf`、`timesbi.ttf` 的字体目录。`pdf_standard_fonts.cjs` 仅适配当前库缺失的字体 import map，不修改安装的运行时。定稿验证还使用 `finalize_native_pptx.mjs` 中的 skill/runtime 路径，迁移机器时需调整。

定稿器不会覆盖已有交付文件；再次定稿时需在脚本中选择新版本文件名。完整重建样例的照片/波形需要原始 MP4/WAV；已有 SVG 内包含实际帧，转换 SVG→PPT→论文图不需要重新下载媒体或调用模型。若直接在 PowerPoint 中改图，应从修改后的文件重新导出论文图；不要运行旧 SVG 导出覆盖这些改动。
