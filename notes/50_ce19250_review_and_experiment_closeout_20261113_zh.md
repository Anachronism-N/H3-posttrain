## 3 当前实际 harness

正式A800实验以 [归档 composition_workflows](../experiments/tx_a800_20261113/code/choreobench/composition_workflows.py) 的冻结合同为准，不能用同名根目录文件替代。

```text
MOSS-Music 的冻结音频候选＋公共结构
  → 全曲大纲
  → 当前规划块＋本方法实际已提交历史
  → 固定流程 / Self-Refine / ReAct / 领域策略与状态组织
  → 草稿提案、结构检查、修订、提交或停止
  → 完整或部分总谱，保留所有失败与费用
  → 独立整曲评价及局部编辑任务
```

ReAct与ours共享工具、全部历史、候选和权限。ours额外使用领域策略提示和确定性的 `choreography_state`：当前块、最近3个已提交动作、最近3个结构拒绝、公开约束及草稿状态。共享信息没有被故意从ReAct输入中移除。

已经实现的控制包括 `submit_block` 单次提出并校验提交、草稿生命周期、无变化修订反馈、重复状态停滞、调用及token预算。未实现的能力包括实际额外听音工具、回改已提交旧块和随用户变化的约束版本；`extra_audio_calls=0`。因此当前贡献应定位为**共享工具上的领域策略与显式状态组织**。

根目录版本没有上述同样的状态摘要，仍有每块一次修订限制；归档版本已改变这些规则。归档代码与主包比较为34份相同、6份不同、44份仅归档存在。下一轮先确定唯一执行合同，不覆盖正在执行的目录；历史实验仍使用自己的冻结源。

## 4 评分与复现问题：先审计，再扩实验

### P0：音乐 unknown 的解析顺序

[evidence_music_fit.py](../experiments/tx_a800_20261113/code/captionlab/evidence_music_fit.py) 的提示规定 `uncertain=unknown`，解析却先处理 correspondence：`uncertain+absent`得到2、`uncertain+partial`得到3，仅`uncertain+explicit`得到null。纯CPU合成记录可以复现。

先核对历史运行冻结代码SHA，再对原 `ratings.jsonl` 和raw离线审计。若历史评分使用了该分支，生成新的解析版本与变化清单，保留旧评分；报告受影响数、unknown变化、共同来源均值与排名敏感性。归档是当前工作快照，不等于每次历史运行源；目前不能断言2,304条结果实际受影响多少，也不需要重跑生成或裁判。

本轮新增 [只读审计工具](../captionlab/music_score_audit.py)，依据保存的分类字段计算建议映射，不自动认证历史代码、原始响应或语义正确性：

```sh
python -m captionlab.music_score_audit \
  --ratings /data/original-music-scores/ratings.jsonl \
  --out-dir /data/audits/music-score-contract-v2
```

输出目录必须不存在；原文件不改动。工具按保存的 `method_id` 分组，该字段可能是每例随机化的匿名代号，不能直接当生成模型。模型级重算还须绑定私有解盲映射及原生成失败库存。真实集群评分文件尚未在本地提供，因此本轮只验证工具行为，不报告全量修正成绩。

### P0：整曲公开条件的注册分母

[e34_final_inventory.py](../experiments/tx_a800_20261113/code/captionlab/e34_final_inventory.py) 跳过未评审歌曲后汇总 `public_five_conditions_complete_lower_bound`，所得是有效子集均值，不能标为全24首完成率下界。例如22首全部满足、2首缺评，注册下界是22/24，不是1。

新后处理应同时输出：注册24首的已确认完成下界、未知比例、上下界，以及仅有效评分的质量均值/覆盖。不能把未知质量填0；“未证明成功”与“质量为0”应分开。该修正仅重算已有记录，不重新调用模型。

### P0：编辑控制题及保护事实口径

[e4_final_metrics.py](../experiments/tx_a800_20261113/code/captionlab/e4_final_metrics.py) 将4个已满足和4个冲突控制题混为 `no_op && goal_complete=yes`；合理拒绝不可满足指令通常不能同时满足动作目标。因此拆开：已满足题看合理保持，冲突题在核实冲突后看合理弃权/保持及权限，unknown分别报告。

同文件还先对全部48题计算保护事实率，再把同名计数字段覆盖为需修改40题，导致部分rate/count分母不一致。改成独立 `required`、`already_satisfied`、`conflicting` 分组，同组count与rate共用库存。

TX作者流程没有接入主包新任务审核接口，作者声明可行不等于独立验收。原稿已满足、目标与保护互斥、邻接不兼容等应单列任务有效性；同时报告全注册端到端成功下界与有效任务上的编辑成功，不能把坏题都解释成编辑能力不足。保留失败任务，不在原48题里悄悄换题。

### P1：全文评价证据与停止协议

- TX的 [长程评分](../experiments/tx_a800_20261113/code/captionlab/e3_final_metrics.py) 仅核合法event ID，未采用主包全文成对评价的前/中/后三段证据合同。对固定总谱追加新协议时，要另立评测版本；引用覆盖也不自动证明语义准确。
- 主包 [native_baselines.py](../captionlab/native_baselines.py) 只采用tokenizer单EOS，实跑 [secondwave_baseline_v3.py](../experiments/tx_a800_20261113/code/captionlab/secondwave_baseline_v3.py) 使用generation_config/config的EOS列表。迁移运行前补多EOS回归及原12条开发协议核对，不能通过修改模型路径宣称复现；无需重生成2,304条已有输出。
- 早期16格与后续80格有路由/并发修复。先以calls及tokens比较费用，墙钟耗时按硬件、副本、并发和路由时期分层。

## 6 哪些内容现在可以写进论文

- 可以写：任务定义、数据构建接口、六模型的真实生成及失败库存、共享工具与状态组织方法、受控执行/解码可靠性、已明确局限的参考相似度和模型辅助评分。
- 可以作为分析发现：文字质量与音乐辅助分排序不同；合法JSON/真实引文不能保证语义；原始动作抽取出现部位继承、方向、时间作用域错误。
- 暂不能写：SFT全面胜过不训练模型、ours真实编舞质量显著胜过ReAct、动作F1已成为可靠质量指标、1127条观察即音乐金标、正式E3/E4已完成。

动作抽取的开放文本审核已拒绝：14篇中67节点为48支持、11部分表达、8错误；25关系为18支持、4错误、3未决。生成式图还有512/2304绑定unknown。因此现阶段将动作/关系F1保留在部分参考诊断，不能把接近零的关系F1解释为所有编舞都错误。BLEU/BERTScore/CLAP同样不代表踩拍、动作可执行性或舞蹈审美。
