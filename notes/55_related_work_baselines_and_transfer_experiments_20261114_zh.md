# 音乐编舞相关工作的对比价值与实验迁移方案

核查日期：2026-11-14。本方案承接[评价量表、消融实验与案例分析](54_benchmark_rubric_ablations_and_case_studies_20261114_zh.md)，面向当前音乐到编舞文本、整曲 harness 和文本编辑任务。本文只记录文献分析与实验设计，不代表这些方法已经接入或产生新结果。

当前优先补充 DanceChat 思路的两阶段文本基线，以及借鉴 ChoreoStudio 的受控编辑和修订成本对照。AtomicDance 主要用于动作组织与重复分析；M³GPT 是必须讨论的任务先例，可在取得可用权重后补充对照。暂不为复现相关工作启动新训练，也不将原论文的动作生成数值直接放入我们的文本评测表。

## 1 四项工作的用途

| 工作 | 与当前任务相关的已核实内容 | 参考价值 | 当前对比定位 |
|---|---|---|---|
| [M³GPT](https://arxiv.org/html/2405.16273v5) | 包含音乐到文本辅助任务；文字主要由风格标注构造 | 确定已有任务边界，避免将音乐到文字本身作为首次贡献 | 可选的粗粒度历史参照，不能等同于细粒度编舞强基线 |
| [DanceChat](https://arxiv.org/html/2506.10574) | 音乐属性描述经 LLM 转成动作指令，再用于 3D 舞蹈生成 | 最接近可独立比较的文字编舞前端 | 优先实现并明确标注 DanceChat-inspired 改编基线 |
| [AtomicDance](https://arxiv.org/html/2607.13978) | 音乐条件的原子动作类别与时间安排，随后补全动作与过渡 | 借鉴过程动作单元、时间组织、动机复现和变化 | 权重与语义映射就绪后，可考虑原子计划的文本适配对照 |
| [ChoreoStudio](https://arxiv.org/html/2610.32325) | 显式群舞计划、计划条件生成、验证反馈和受控干预 | 借鉴规划与执行分开评价、局部编辑及计算预算控制 | 优先迁移实验设计，不作为当前单人文本任务的直接同任务模型 |

## 2 M³GPT 的先例与任务差异

M³GPT 已发表于 NeurIPS 2024。原文 §3.3 以音乐的风格标注构造文本，例如“a person is dancing Jazz”，用 music-to-text 和 text-to-dance 辅助任务建立模态联系。Table 15 确实在 AIST++ 上报告 A2T 的 BLEU-4 和 CIDEr。原文 §3.4 还介绍了五秒动作生成训练与基于音乐、历史动作的递归长序列生成。[会议记录](https://proceedings.neurips.cc/paper_files/paper/2024/hash/316648eb8b4ffb6010f531b07848c300-Abstract-Conference.html)、[原文 §3.3、§3.4 与 Table 15](https://arxiv.org/html/2405.16273v5)

其风格级文本目标与我们的动作、身体关系和时间组织描述不同。若将它纳入六维评价，应说明目标粒度差异，不能仅凭细粒度维度低分得出全面超过 M³GPT 的结论，也不能将其原论文数值与我们不同数据、不同协议的结果直接比较。

它使用 BLEU 和 CIDEr 是相关工作的事实，不构成恢复 BLEU 为本项目主指标的理由。我们的主评价仍针对编舞方案与音乐的关系，参考文本一致性另列。

[官方仓库](https://github.com/luomingshuang/M3GPT)公开了代码，但本次核查未确认可直接运行 A2T 的完整权重与推理配置。取得模型、音乐 tokenizer 和任务入口后再评估接入，不以重新训练复现作为当前短期实验前提。

## 3 优先补充 DanceChat 思路的文本基线

### 3.1 原方法和可复用部分

DanceChat §3.3 使用专门工具提取 tempo、chord、key、beat 等音乐属性，组织成模板描述，再由 LLM 生成动作指令。提示中包含时长与舞蹈风格，并刻意避免方向词和过细空间信息。原文使用五秒片段和 GPT-4o；主要结果评价生成的 3D 舞蹈，而非独立的文字编舞质量。[DanceChat §3.3 与 §4](https://arxiv.org/html/2506.10574)

我们只适配它的文字前端，无需加载或训练后续动作生成器：

```text
同一段原始音乐
→ 自动提取音乐属性或事实
→ 固定模板的音乐描述
→ 通用语言模型生成编舞文本
→ 独立的六维评测
```

[公开项目页](https://dancechat.github.io/anon/)的 Code 按钮在本次核查中仍指向占位地址。因此，这一实验应标记为基于论文思路的适配，不称已运行作者官方实现。

### 3.2 最小对比表

| 方法 | 生成路径 | 回答的问题 |
|---|---|---|
| 通用音频模型直接生成 | 音乐和统一编舞提示直接生成文本 | 通用能力能否完成任务 |
| DanceChat-inspired 两阶段基线 | 自动音乐描述，再生成编舞文本 | 无需训练的分析与规划流程能达到什么水平 |
| 专用 SFT 模型 | 原音乐和统一任务说明生成文本 | 任务训练是否超越直接提示和两阶段方法 |

若同一通用后端同时支持音乐输入和文字输入，可优先用相同权重比较直接生成与描述中介生成；这样减少模型家族差异的混杂。不同后端的比较属于系统比较，不能把全部差异归因于音乐描述中介。

### 3.3 公平执行条件

1. 使用相同音频切片和实际时长。当前样本若为 5.0625 秒，就统一提供真实时长，不暗中改裁成其他长度。
2. 舞蹈风格由音频预测，或作为所有方法共享的公开条件；不得只给某个方法提供测试 GT 舞种、动作标注或视频信息。
3. 自动分析结果保留不确定性和失败状态，不能在属性识别失败时填入 GT。固定音乐描述模板，保存中间产物。
4. 更换原论文的音乐提取器、LLM 或提示词时，在方法名称和配置中明确披露。使用音频语言模型代替符号分析工具也属于适配。
5. 生成端音乐描述与评价端独立音乐观察分开，禁止将评审证据直接输入生成方法。
6. 统一任务要求，采用适合各模型的接口和可比解码约束。不要要求某种专用句式，也不因方向词缺失而机械扣分，只检查动作理解所需的信息。
7. 报告音乐分析和文字生成的合计调用、token、耗时及失败率。两阶段基线与直接模型的计算量差异必须可见。
8. 保留原始输出，不在评分前自由润色或补动作。系统提示、模型版本、音频和输出标识与成本共同归档。

## 4 AtomicDance 的动作组织启发

AtomicDance 将动作视为有时间过程、可以重复和变化的单元，规划其类别与时间，再生成动作与过渡。它的结构一致性 R 指标考察相似音乐片段对应的生成动作特征相似关系；该指标仍依赖动作特征，不是文本分数或动作类别准确率。[原文 §3 与 §4.2](https://arxiv.org/html/2607.13978)

### 4.1 对闭集动作重复问题的迁移

建议将“动作核心、变化属性、时间与衔接关系”分开记录。方向、幅度、速度、配合部位或持续方式不同，可能是同一动机的不同实现，不宜全部压成一个标签。文字表达保持开放，归一化的动作事件用于分析，不反过来限制生成词表。

评价重复时同时检查两件事：

- 相似音乐段落是否能形成可辨识的动机复现或变体。
- 不同音乐段落是否被同一模板无差别覆盖。

只检查第一项可能奖励所有地方重复同一个动作；只追求多样性又可能奖励无组织的变化。由此形成的文本事件或语义相似度诊断，需要固定抽取方式并验证，不能沿用 AtomicDance 的原指标名称和运动数值。

### 4.2 可运行性和改编基线边界

[官方仓库](https://github.com/oceanflowlab/AtomicDance)公开代码并提供原子标签数据下载说明，标签使用有限类别，不能据此宣称解决了动作闭集问题。README 提供 checkpoint 链接，但同时写明权重待发布；本次未核实链接中的权重是否完整可用，不能断言权重不存在，也不能宣称开箱可跑。

若取得规划器权重和类别语义映射，可考虑：

```text
音乐
→ AtomicDance 规划器预测原子类别与时间
→ 固定且保留原信息的文本转换
→ 六维及时间组织诊断
```

接入条件如下：

1. 使用模型预测的计划，不能使用 ground-truth 或 oracle 计划。官方推理实现包含不同计划来源，必须锁定来源并记录。
2. 单独导出规划结果，避免为了文字比较额外运行完整动作补全模型。
3. 类别名称与语义映射需要来自公开定义或统一核验，不能凭类别 ID 猜测动作。
4. 文本转换不得由另一 LLM 自由增加方向、部位和衔接细节。若增加，则应作为组合系统单独命名。
5. 在论文中标记为原子计划的适配基线，说明它与开放文字编舞的表达范围差异。

## 5 ChoreoStudio 的实验迁移

ChoreoStudio 显式建模群舞的编队、变化时机和舞者职责，再评价计划及其实现。附录 A.5 的编队实现误差比较计划与生成动作；Director 的 transition F1 和匹配转移的时间偏差依赖目标标注，mobility 误差比较预测与伪标签。附录 C.1 的受控干预还检查生成动作对编辑目标的响应，不能把这些阶段混成同一个指标。[原文 §3、附录 A.5 与 C.1](https://arxiv.org/html/2610.32325)

本次未核实可直接部署的作者官方实现和权重。其群舞生成器不作为当前单人文本任务的紧急复现目标，优先迁移实验问题。

### 5.1 受控编辑实验

| 编辑类型 | 操作 | 当前可评价内容 |
|---|---|---|
| 局部动作替换 | 替换指定区间的动作，其他内容保持 | 目标满足、非目标保持、相邻边界衔接 |
| 时间编辑 | 对已有明确时间的事件提前、延后或缩短 | 计划中的编辑时间与要求的偏差，不称真实动作执行误差 |
| 动机编辑 | 后续段落复现前段动机，同时改变一个指定属性 | 动机是否保留、属性是否改变、是否引入无关修改 |
| 跨段组织调整 | 改变一个段落的动作安排，保留其他段落及全曲约束 | 局部修改与全局一致性，约束满足及保护范围 |

编辑约束和保护项在生成前冻结。不能以字面差异直接衡量语义破坏，也不能仅因目标动作出现就判编辑成功。现有无时间戳的短 caption 不自动提供时间编辑真值；应使用具有明确时间的计划或专门构造并核验的编辑任务。

### 5.2 修订与计算预算对照

ChoreoStudio 附录 C.4 比较了相同总去噪预算下的反馈修订、较长单次生成和独立多样本择优，以区分反馈收益与计算或选择收益。[附录 C.4](https://arxiv.org/html/2610.32325)

迁移到当前 harness 的建议对照为：

| 对照臂 | 执行方式 | 用途 |
|---|---|---|
| 原稿 | 保留一次生成的原始编舞 | 修订前参照 |
| 反馈修订 | 同一原稿经固定反馈流程修订 | 检验反馈驱动改进 |
| 独立重采样并择优 | 使用相同后端和任务证据，独立生成候选，再用固定选择器选取 | 控制额外采样与筛选的收益 |

冻结后端、输入证据、候选数和预算规则，计入反馈、修订、采样及选择的全部成本。相同调用上限不等于相同实际成本；无法严格匹配时报告质量与实际成本关系，不宣称等成本优势。最终评价独立于反馈和选择过程，不能只使用系统自身评审的分数证明改进。

当前 harness 的结构校验不自动等于可靠的编舞语义反馈。实验需要明确反馈来自什么证据、能检查什么，以及修改的真实内容，不能把多调用工具本身当作机制收益。

## 6 哪些指标能迁移

| 评价内容 | 当前音乐加文本能否直接评价 | 处理方式 |
|---|---|---|
| 动作具体性、关系、时间组织、音乐响应 | 可以评价文本方案，但需验证 rubric | 使用文档 54 的六维协议 |
| 文本计划中的局部编辑与保护 | 有明确原计划和编辑要求时可以 | 评价语义约束、保护项及计划时间 |
| 原论文 A2T 的 BLEU 或 CIDEr | 可计算参考一致性，但数据与目标粒度不同 | 不与原论文数值直接拼表，不替代质量评价 |
| 运动 FID、动作特征多样性、PFC、BAS | 不能由文本直接得到 | 需动作输出、相应特征及统一执行条件 |
| AtomicDance 的结构 R | 不能直接用纯文本沿用 | 原指标依赖动作特征；文字版本需独立定义和验证 |
| ChoreoStudio 的编队实现误差 | 不能直接由文字计划得到 | 需计划和生成的群舞几何 |
| Director 的 transition F1 与时间偏差 | 需明确转移目标及时间标注 | 现有短 caption 不提供对应真值，不把音乐边界自动当动作唯一真值 |

若以后接入共同动作或视频执行器，须另设下游实验，并区分计划质量和执行器能力。当前论文不应借用运动指标名称为纯文本评分背书。

## 7 短期实验优先级和论文定位

| 优先级 | 工作 | 资源和前提 |
|---|---|---|
| 优先 | DanceChat-inspired 两阶段文本基线 | 原音乐、自动音乐分析工具或模型、现有语言模型服务；无需训练 |
| 优先 | 局部编辑及反馈修订与重采样对照 | 原始计划、冻结编辑要求、外层服务、独立评价；复用现有候选与原稿 |
| 补充 | AtomicDance 启发的动机与模板分析 | 已有整曲文本和音乐，核验后的动作事件或语义表示 |
| 条件具备后 | M³GPT A2T 推理、AtomicDance 规划器适配 | 可用权重、实际推理入口、必要 tokenizer 或语义映射 |
| 暂缓 | 完整动作生成系统复现或新增训练 | 不是当前文本 benchmark 的运行前提 |

与文档 54 的关系：新增两阶段方法属于强基线比较，不替代同基座 M0 和音频干预 M1；编辑实验细化 E1、E2；反馈与重采样对照细化修订及成本实验。总纲 H1、历史 H2 仍需在当前整曲写作入口落实，不用相关论文的方法描述替代本仓库实现证据。

论文应准确承认音乐到文字、文字引导舞蹈和显式编舞规划的先例。五秒动作专家递归扩展到长序列也已有探索。我们的贡献应围绕细粒度编舞数据与专用模型、整曲文本组织和编辑，以及经过验证的独立评价协议展开，不笼统声称首次音乐到文本或首次短模型扩长。

所有改编方法注明来源、实际后端、工具、输入条件和输出转换。公开实现状态按核查日期表述；未验证可运行不等于作者没有发布。新增实验结果在统一数据和协议下生成后再进入论文表格。
