# 面向 CVPR 的音乐文本编舞实验方案

日期：2026-11-10。代码与结果审阅基点：`350718a420676718ef5521978a9d2c38ec454279`，分支 `codex/music-choreo-benchmark`。本文规划论文实验，不包含新训练、模型推理或质量评分。

建议围绕“整曲音乐到文本编舞及指令编辑 benchmark，harness 作为可复现 baseline”安排 **9 组实验**。这是研究设计建议，不是 CVPR 规定的实验数量。九组可以复用数据、候选和评审；不需要九套训练，也不需要所有开关做笛卡尔积。

benchmark 应证明任务与评价有意义，并让强基线的能力和不足可以复现；若同时主张方法优势，还需证明所提方法在质量、可控性或成本上改善其中一部分。基线的中性或负结果并不使 benchmark 自动失效。不能用通过测试、输出合法或模型自评 accepted 替代质量证据。

## 1. 最新证据及论文定位

本轮从 `de2651b` 拉取并快进到 `350718a`。新增两次提交只改四个文档文件：服务器 v24 原件审计回执，以及对现有输出的实质内容初审；没有新 Python 实现、Captioner 训练或正式独立评价。

| 已有证据 | 可以说明什么 | 不能说明什么 |
|---|---|---|
| v24 核验三歌九臂、21 次历史修订调用及六份音频切片，通过原件绑定 | 这批历史执行和保存产物一致，旧审计工具缺口未造成已发现的数据错配 | 作品质量好，或回听有效 |

| 九个修订最终稿七个未改，两个各只改一处 3.25 秒 | 当前整曲比较难显示变化；需要审查所有候选及局部收益 | 修订永远无效 |
| 助手审阅 227 事件、六候选、24 诊断 | 可用于开发假设和失败案例 | 独立人类盲评、直接听音评价 |
| 五组 Captioner 小预算训练已完成，但三例测试存在多次循环/截断 | 去时间戳、去 JEV、扩大 audio LoRA 尚未解决这些案例 | 训练专家优于所有未训练模型 |

重复数按原 Unicode 正文完全相等计算，详见[报告43第9节](43_candidate_review_audit_and_next_experiments_20261110_zh.md)。它与现有通用评估器的归一化正文计数不是同一个定义。当前三首是开发歌曲 ID，来源独立性尚未完全核实，不能作为三个已认证独立来源组。

**论文范围建议：** 保留整曲编排、受控文本编辑、评价协议三项主线。Captioner 作为局部专家独立研究；自动回听修订有正证据再作为方法优势。没有跨任务、隔离测试的持续自我改进实验，就不主张 RSI；没有偏好优化更新，就不称 DPO/RL。

CVPR 官方涵盖 benchmark、人体视觉、多模态和视频生成。本文建议加强视觉动作依据或受控下游验证，这是针对投稿定位的研究判断，并非官方要求每篇论文必须生成视频。只有音乐与文本、没有可靠动作依据的方案，视觉贡献会较难论证。[CVPR 2027 征稿范围](https://cvpr.thecvf.com/Conferences/2027/CallForPapers)

## 3. E1 数据与任务质量

发布物至少包括音乐来源索引、canonical 音频时钟、公开输入、动作计划格式、编辑任务、评估规范、固定划分及 baseline。不能只发布几个生成 JSON 和运行脚本，便称为完整 benchmark。

1. **按源歌曲及近重复关系划分。** 同歌不同裁剪、不同编码、重混的已知关系、对应视频和其 caption 不能跨开发/测试。记录已知 Captioner 训练源交集；未知的基础模型预训练重叠如实注明。若承诺艺人泛化，另做艺人隔离，不默认歌曲隔离等于艺人隔离。
2. **覆盖统计。** 报告 3–5 分钟整曲占比、时长、速度/节奏变化、结构重复程度、能量变化、音乐类型、器乐/人声及来源分布。预测的拍点、结构边界须标明算法与可信状态。
3. **两种参考作用分开。** 视频动作描述可检验“说的动作是否在画面中发生”；它只提供一种实际编舞，不是该音乐唯一正确答案。音乐到编舞评价允许多个合理答案，不以参考文字相似度判胜。
4. **编辑任务独立审定。** 保存原计划、用户可见指令、允许区间/字段、需保护事实及评价依据。测试答案和评价员隐含检查点不进入模型提示；用户明确提出的保护要求则给所有方法。
5. **标注 QA。** 抽取视频支持的动作事件、相邻边界和编辑指令，由两人独立核验；报告一致率、无法判断率及原始分歧。模型可以提草稿，不能自己认证草稿是真值。

原 NLF/MotionScript/VLM 产物可作为候选标注来源，但要核验视频时间、人物、朝向和动作事实。标签空间扩大是否减少闭集偏差需要单独证据，不将同义词变多算成新动作空间。

建议先用 6 首开发歌和另外 6 首协议 pilot 测流程与评审耗时，已查看并调过方法的歌曲归入开发池。预算草案为 **20 个开发来源组＋40 个隐藏测试来源组**；最终数量按 pilot 方差、评审负担和覆盖需求确定。这是小型 benchmark 预算，不是统计充分性或“规模足够发表”的保证。

## 4. E2 局部 Captioner

主比较至少包括现有 `standard6040` 专家、官方 Omni-Instruct 加明确编舞提示，以及资源允许时另一种可访问的强音频理解模型加同任务提示。确切模型/权重版本在开跑前冻结，不将描述乐器的观察器提示冒充编舞强基线。

先完成[报告42 C0–C2](42_latest_review_and_experiment_plan_20261110_zh.md)：回收已有训练/评分原件，八个新来源、五 profile、40 条生成。这个小测用于诊断和选型，不是正式模型排名。若在论文主张任务训练有增益，再在隔离测试来源上增加足够覆盖的局部片段；同歌多片段按歌聚合，不能当独立歌曲。

评价音乐适配、动作具体性、书面可执行性、衔接、病理循环、停止/截断和无法判断。自由生成质量是主证据；参考前缀 NLL、EOS 概率和 true/random 似然差是诊断。不同目标 token 序列的 NLL 不直接排质量名次。

如需要解释训练机制，复用已完成的 timed/untimed、CE/JEV、a4/a16 结果并标明可比配对；不为了凑消融启动新一轮训练。未证明专家优于零样本模型时，benchmark 仍可成立，但不能写“训练专家必需”或“比任何未训练模型更好”。

## 5. E3 整曲规划主实验

不要强行加入用户已指出不合理的“一次读全曲然后一次吐出总谱”作为核心弱对照。强全局基线应采用普通的分层规划，让它获得同样公开证据和合理预算。

| 方法 | 操作 | 比较目的 |
|---|---|---|
| B0 局部直接编译 | 同一候选库，冻结确定性选择/编译规则，不人工挑最好候选 | 只靠局部专家能达到什么程度 |
| B1 独立逐块 | 同一文字模型逐块组织候选，不用跨块记忆和全局设计 | 局部组织能力 |
| B2 通用分层规划 | 全局结构/主题大纲＋因果逐块生成；同候选、公共证据与合理历史 | 排除收益仅来自常见分层提示 |
| B3 所提 harness | 在 B2 基础上加入验证后的记忆、时长预算等机制；修订先单列 | 主方法 |

方法效果表固定候选库、结构证据、模型版本、采样设置和格式合同。B0 不能可靠编译某例时登记失败，不额外免费调用 LLM。B1 是否去全局大纲、B2 的历史呈现及各方法调用上限均预登记；E5 再单独隔离机制。所有方法使用同样的机械合法性检查，给基线合理提示开发预算。

另列系统效果表时，才允许更换专家、观察器或模型；分别记其额外成本，不能将两张表混作 harness 单因素收益。有余力可在第二个文字模型上复核 B2/B3，避免只对一个服务提示有效；主张模型通用性时该复核应列入主实验。

**全曲主终点建议为音乐适配和长程编排质量，分开报告。** 两名评价者听完整首音乐并查看全计划，隐藏方法名、内部接受结果和成本，随机方法顺序，允许平局/无法判断。登记舞蹈/音乐经验、开发参与及先前材料曝光；普通听众偏好与有经验者的动作判断分开解释。局部片段补评具体动作、时长负担和边界，不拿片段偏好代替全曲组织。主题回归、动作发展、留白及结尾是否成立都要结合上下文，不能要求所有动作都不同。

40 个测试来源×4 方法＝160 份计划；每份两人评价＝320 份全曲评价记录，仍只有40个来源组。若每份用时8–12分钟，则合计约43–64人时；这是示例预算，要用 pilot 实测替换。

## 6. E4 用户指令式编辑

固定同一份源计划再比较各编辑方法；不能让每种方法只编辑自己生成的不同原稿。原稿来源要预先抽样并分层，避免专选对某方法容易的内容。

第一版优先覆盖当前权限能表达的四类指令：局部动作替换、力度/幅度/密度调整、保持某身体部位动作而改另一部分、结尾/主题发展调整。每个任务提供必要前后文和保护要求；不把“膝盖不变”偷换成某段字符串必须原样保留。

| 对照 | 设置 |
|---|---|
| No-op | 原稿不变，校准已满足指令/保护分数；不是有意义编辑的强基线 |
| 普通 LLM 编辑 | 同模型、同指令/证据/权限＋共同机械控制器 |
| 所提上下文编辑 | 同预算与权限，使用边界/主题记忆和目标分解；必要时独立评价修订选择 |

正式规模草案为40首×3个任务＝120任务，三条件共360个任务输出状态，其中 no-op 不调用模型；各两份评价为720条任务评价。应先计入评审工时，再冻结全量或来源分层的人工子集；剩余机器评分不能冒充完整人评。

每任务分别判断：目标是否满足、受保护动作事实是否保持、修改范围是否合法、前后衔接是否受损、音乐适配是否下降。**联合成功要求预先指定的必需项同时通过**，不能把保护率很高但没完成指令算成功。失败、未知和未完成评价分别保留，报告有效评价覆盖率；可给将未判定视为未证实成功的保守下界，并明确其分母。

增加少量已满足、歧义、约束冲突的控制任务，评价合理 no-op/弃权，避免“每次必须改”。若论文声称多轮编辑或时间重排，就另加连续3轮任务或独立时间权限轨道；当前只改 action 的执行器不能完成真实 JSON 时间平移，不将 prose retiming 算作支持。

## 7. E5 记忆与动作预算消融

两项机制分别回答“保留衔接信息如何避免照抄”和“动作密度是否适合时间”。先做固定原前缀的局部重放来定位，再跑完整轨迹检验误差累积。仅重放几块不能宣称整曲提升。

| 记忆条件 | 保留内容 | 状态 |
|---|---|---|
| full | 当前 recent8、身体部位末事件正文、主题 recent_examples | 已实现，有旧三歌开发对照 |
| metadata_only | 时间、轨道、声明状态、主题计数及大纲，移除三条历史 event.action 路径 | 已实现固定原前缀重放；全曲轨迹仍待实现/验收 |
| boundary_compact | 仅保留触及当前边界的最近实际动作，每个稳定事件 ID 正文一次；加状态/计数 | 待实现 |
| none | 当前 use_history=false | 已实现，有旧三歌开发对照 |

metadata_only 仍有大纲和声明状态的动作语义，不叫“完全没有动作信息”。boundary_compact 先用确定性提取，不加 LLM 摘要器；不能只去 recent8，却让同一全身动作在六个身体部位槽里重复暴露。

动作预算比较三条件：原动作提示；随事件秒数/可靠节拍数变化的动作复杂度预算；**时长无关但总体输出长度相当的控制**。主要改变可表达的顺序动作/状态转换数量，不将同时发生的左右肢体动作一律当作多个先后动作。输出更短不自动表示更可执行。等长度控制规则在开发集校准，测试期不按结果后验截断或重抽。

最省的设计是四记忆条件共用开发集校准并冻结的时长相关预算 B*，然后在开发集选定的记忆 M* 上增跑原预算和等长度控制，共 **6 个独特组合**。报告它不覆盖全部交互；若结论依赖记忆×预算互作，补相应组合。开发选择 M*/B* 后冻结，正式测试不再挑赢家。

主要评价衔接、主题发展、书面可执行性与音乐适配；逐字复制率、动作句长度、每秒顺序转换仅作诊断。合法副歌复现不能按“重复”扣分。采样至少在预先选定的来源子集增加第二个 seed，按来源聚合，不把多个 seed 当独立歌。

## 8. E6 自动诊断、编辑、选择与回听

这里研究模型自己发现问题，与 E4 的用户显式指令是两个任务。先让诊断器提出当前 editor 能处理的内容问题，并允许弃权；修复权限仅 action 时，不优先提出必须改 JSON 时间的错误。

| 条件 | 用途 |
|---|---|
| 原稿 | 零新增修订成本基线 |
| targeted＋正确观察＋editor＋selector | 完整自动修订 |
| random＋对应位置观察＋同 editor/selector | 选点是否有价值 |
| targeted＋正确观察＋editor，直接保留候选 | 复用同候选，隔离 selector；不重新采样 |
| targeted＋text_only＋同 editor/selector | 回听的额外价值 |
| targeted＋已审错配观察＋同 editor/selector | 主张音乐证据有效时加入；排除只多了一段文本的作用 |

固定原稿、诊断、目标数量、修改权限与调用预算，审阅全部候选，不只评 accepted。分别记录目标必要性、候选相对原稿的改善、selector 的误接受/误拒绝和最终收益。所选位置的有效率不是全曲问题召回率；测召回需要独立标注完整搜索范围的真实问题。

当前 targeted/random/text_only、候选导出和原件审计已实现；精简历史、能力匹配的内容诊断、错配观察等尚无完成实验。错配必须保留 donor 来源身份，不修改原音频哈希来伪装同一观察。

每歌单目标、一次编辑 seed 的上述设计，若现场生成错配 donor 观察，最多约12次调用：诊断1、目标/随机位置/donor观察3、文字编辑/比较8。错配观察已有冻结缓存时，增量可降到11次，但其生成成本另计，不能把两类观察误算成只有两个独立输入。原稿和候选银行成本另计；直接接受候选不增加调用；实际 no-op/失败按真实账本记录。在此单步设计推广到 r 个目标、T 个编辑 seed 时，诊断/观察跨 seed 复用的上界是 1＋3r＋8rT；错配缓存已备时增量上界为 1＋2r＋8rT，前提是条件和缓存合同保持一致。

若单次只有无信息润色，先修内容目标，不直接把修订次数加到几十次。出现实质候选后，再测每歌0/1/3个修订目标的质量—成本关系；重复编辑同目标与增加目标覆盖需区分。

## 9. E7 评价有效性与音乐条件利用

采用三层报告，不急于把所有指标加权成一个总分。

| 层级 | 指标 | 解释 |
|---|---|---|
| 可机械核验 | schema、时钟、覆盖、范围、字面保护、实际调用/失败 | 实现正确性，不是编舞质量 |
| 语义与音乐 | 音乐适配、长程组织、边界衔接、时长可行性、编辑目标和保护 | 以独立人评为锚；自动评分需校准 |
| 视觉实现 | 计划中的动作能否观察到、编辑是否体现、非目标动作是否保持 | 条件于执行器/人体估计器能力 |

量表给出1/3/5分的具体锚点；例如高音乐适配要求有可指出的速度、力度、组织与听到的变化对应，不能仅因文字说“跟随节拍”给高分。长程组织要求听完整曲。文本可执行性只判断可理解的时间/动作关系，不冒称已验证生物力学安全。

建立分离的评价校准集：真实失败＋人工确认的局部扰动＋合理改写/合法重复。覆盖复制而不发展、过密顺序转换、结尾自相矛盾、跨权限修改、纯粹改词不改动作，以及等义改写、合理反复和同步动作。先用 pilot 约40–60个校准对，按源歌曲隔离调参/留出部分；合成错误类型不能泄漏给 judge。

报告人工一致性（有序量表可用加权 kappa/ordinal alpha，并保留原始分歧）、自动评价与人评的配对一致率/秩相关、错误类别准确性、误罚合理编舞、弃权及覆盖。模型 judge 若与生成器同源要披露；更换模型也不自动构成独立真值。

音乐条件控制有两层：

- 局部专家：同提示、同 seed，输入真音频、人工审查的跨源错配和同几何静音。判断输出是否对实际音乐适配，而不是仅文字发生变化。多解任务中随机歌曲不天然构成错误负例。
- harness：固定候选和原稿，仅改变局部观察，用于隔离“额外观察”的价值；这不代表整个系统对原音频的因果利用。系统级另需同目标任务重建真/错配音频证据链，不能固定旧候选却宣称测了全系统换歌效果。

统计以来源组为单位。先在歌内合并事件/任务/seed，再做配对差异与来源组 bootstrap 区间。预先确定主要终点和对照，其余探索性分项分开报告；小样本不凭一处显著值宣布全面胜出。评审不足、unknown 和来源关系未知不能悄悄填成0或成功。

## 10. E8 长时域、效率与稳健性

主要报告真实3–5分钟歌曲；可用30/60/180/300秒子集研究长度影响，但同歌前缀是相关样本，不是四首独立歌。对30/60秒裁剪应声明任务结束位置，避免把原曲中段当自然全曲结束来评价。

每方法记录局部音频提案、大纲、逐块规划、诊断、观察、编辑及比较的调用/tokens、运行时间、峰值显存、失败/重试/弃权。共享候选成本单列，同时给包含共享成本的端到端成本；缓存复用只能在增量成本里减去，不能说整曲生成只花一次修订调用。

补充结构证据低置信、节拍偏移、缺失局部候选等小规模扰动，保留明确缺失状态，验证 graceful fallback。当前实际 v11 使用 meter 未验证的10.125秒回退块，不能宣传为已验证乐句分割。只有论文主张乐句/节拍分割贡献时，才增加固定窗与节拍/结构分割消融，并尽量控制单位数和调用量。

失败率与有效输出质量并列展示。恢复/哈希/审计/浏览器测试作为可复现性材料，不给它们加编舞质量分。

## 11. E9 视觉动作证据与固定执行器

建议保留文本编舞为主任务，同时落实以下两条路径中的至少一条；资源允许时两条都做。

**路径A：动作标注的视觉有效性。** 使用有许可的配对舞蹈视频，核验动作事件、主体/方向、时间及编辑语义。按身体部位和动作层级报告视频支持率、遗漏与错误，不以 MotionScript 自动输出自证。视频可支持动作表达与标注可信度，不证明生成计划优于其他音乐编舞。

**路径B：固定下游执行器。** 用已经能稳定运行的 H3 或 text-to-motion 执行器，固定模型权重、参考人物图、原音乐、窗口、种子与采样配置，只替换 B2/B3 的计划或编辑前后计划。预选含过渡/编辑目标的片段，并保留所有结果。先10片段×2条件×2种子＝40个短结果；有资源扩到20片段×3条件×2种子＝120个。片段和种子不扩大独立音乐来源数。

分别评计划动作实现率、编辑体现/非目标保护、音乐适配和视觉质量。生成失败和人体估计失败单列；没有足够动作时不要强算 motion FID/BAS。固定执行器的局限可能掩盖好计划或自行修补坏计划，因此文本/视频两层结果一起看。5秒视频证据不证明已生成连续3分钟舞蹈。

[EDGE（CVPR 2023）](https://openaccess.thecvf.com/content/CVPR2023/html/Tseng_EDGE_Editable_Dance_Generation_From_Music_CVPR_2023_paper.html)可借鉴音乐舞蹈质量、物理合理性与用户研究分开验证的思路。其输出为运动，不是本任务文本总谱的直接基线；只有在输入、输出和评价协议兼容的下游任务中才作数值比较。不能把运动 FID/BAS 套在文字或样本边界上。

## 12. 资源和执行顺序

本阶段**无需新训练**。已有专家的推理、文本服务、可选观察器和可选视觉执行器按阶段加载；数据 QA、人评和原件分析只需 CPU。显存和每歌耗时沿实际加载合同测量，不根据参数名猜单卡配置，也不让几个大模型无必要地同时驻留。

### 14.4 实质动作初审，而非以“短/不同”判胜

- **电子case：局部冗余减少，但短槽仍紧。** full完整复用长串，174.71–175.96秒包含body roll→肩背isolation→低lunge→pivot→手臂sweep→再次chest isolation；metadata_only缩为“body roll后肩背isolation”，去掉多个先后转换。第一/第三槽仍包含起身、chop/twist/步法或下沉/方向改变/肩部wave/arm thrust，1.25–1.3秒是否足够仍待更明确预算。不是去重即证明可执行。
- **摇滚case：仍未解决关键时间负担。** 169.605–170.355秒的metadata_only仍写“dynamic spin landing on one leg, followed by staccato arm pumps and floor touches ... head snaps”；仅0.75秒、含转身落地再多次动作。它减少了full的pivot/hop/lunge串，却仍过密。相邻两个槽又复用arm pumps/floor touches/head snaps短语；零“完整旧action匹配”并不意味着语义重复消失。
- **原声case：有局部结尾内容变化，连续性未被证明。** full末槽继续“freeze→foot tap→arm thrust→pause”，metadata_only换成一腿后伸、前倾、手指模仿strumming、弯膝并保持stillness；不再机械复用M8长句，结尾操作更少。但前一原事件状态为空，不能断言新首槽step-hop与此前freeze之间真实姿态衔接已成立。乐器模仿/末strum也是候选文字启发，未由本轮直接听音确认。

两臂全是body轨道，JSON时间/主题/引用合法且原前缀相同；这些只证明合同与局部比较有效。**初步支持减少完整历史正文能减轻本批块的长串照抄，不能直接宣布metadata_only全曲最优或音乐贴合提升。** 目前是三个专选问题块、单seed的开发探针，不覆盖未见歌曲/整曲轨迹/记忆与预算交互。两臂共同仍选三个槽，当前提示与菜单的事件数量偏好未随去历史解决。
