# 音乐到文本编舞 Benchmark 协议草案 v1

状态：协议与实现合同，核验日期 2026-11-04；尚无正式发布数据集、真实模型排行榜或已校准的新质量指标。本文以 [CONTRACT.md](../CONTRACT.md) 为字段合同，以实际实现与验收记录区分已支持功能。仓库 fixture 只验证软件流程，`mock` 输出只验证接口，二者不构成 benchmark 数据或 baseline 实验结果。

## 1. 研究对象与三条赛道

目标是评估给定音乐下的开放自然语言编舞计划及其局部修改。音乐与编舞是一对多关系；参考描述是可接受实例和约束证据，不是唯一标准答案。文本计划有效不等于人体动力学可行，也不等于任意视频生成器能执行。

| 赛道 | 公开输入 | 输出与主要问题 | v1 边界 |
|---|---|---|---|
| `local5s` | 约5秒音频、统一任务 brief、可选公共音乐工具结果 | 可定位的局部动作文本；音乐适配、明确性、重复与不确定性 | 现 native expert 实际观察窗为5.0625秒；标准 profile 采用16kHz单声道、81,000样本，不能将其默写为80,000样本。不能把两个模型文本窗当真实动作起止真值。 |
| `fullsong` | 180–300秒完整歌曲、统一 brief、公共音乐结构预测 | 全曲时间线与主题动作；段落组织、主题回归和变奏、过渡、成本 | 模型观察窗与计划执行区间分开。局部窗可重叠，输出所有权区间不能因此重复计时。 |
| `edit` | 原计划、用户指令、允许/修复事件ID、保护字段 | patch与修改后计划；目标达成、保护保持、边界、连续多轮稳定性 | 当前合同只替换已有事件字段；不支持增删事件、改ID或全曲顺延。插入、删除、复杂 retiming 属于后续协议，不列为已实现能力。 |

三赛道分别报分。首版不要求训练新模型或完成整曲RGB视频，不将 harness 改进作为参赛条件。独立短窗拼接、普通全局提示、分层规划等是可替换 baseline，不是基准定义本身。

## 2. 时钟、结构与表示

1. 所有内部时间为 canonical 音频采样率下的整数样本下标，采用半开区间 `[start,end)`；秒数仅为展示。正式音频 profile 推荐先统一为16kHz单声道，保留原始文件身份、变换记录和样本数；schema 本身允许其他明确采样率。
2. `fullsong` 要求 `180 * sample_rate <= num_samples <= 300 * sample_rate`。`local5s` 的源歌曲、原文件及裁剪偏移另存公开来源映射；片段内部时钟从0开始。该映射不是擅自加入严格 Song schema 的字段。
3. `music.beats/downbeats/sections` 是参赛者可见的工具预测，记录工具身份与来源。sections 覆盖全曲且无缝分割；未知结构可明确为单一 `unknown` 段。不得以固定BPM臆造拍点，也不得把工具预测当人工真值。
4. Plan 使用 `motifs` 和开放文本 `events`；正文动作不局限于预设动作类别。`attributes/entry/exit` 的未知值为 `null`，不能为通过校验编造支撑脚、接触或朝向。
5. 同轨事件不能重叠；不同身体轨道可同时活动。`body/upper/lower` 与其子部位冲突按合同报告。覆盖率按时间并集报告；休止需显式动作与属性。覆盖高、motif ID 多或动作词多都不是质量分。
6. 保留模型原始输出、规范化规则和失败信息。固定观察窗被转换为计划区间只代表排程约定，不宣称精确动作边界已经被模型预测。

## 3. 公开输入与私有评估物理隔离

| 参赛者可见 | 仅评估方可见 |
|---|---|
| 音频与校验身份、时钟、公开 brief、公共结构预测、数据划分和公开来源映射 | 独立人工音乐结构审计、可接受约束与编舞实例、质量评审及其标注说明 |
| 编辑原计划、自然语言 instruction、allowed/repair IDs、protected 字段、该计划哈希 | `goals`、`semantic_goals`、人工目标解释、反事实配对答案及最终评审 |
| 公开验证器与格式规则、开发集可公开评估材料 | 隐藏测试答案、评审身份和未公开校准材料 |

编辑 Task 中的 `source_plan_sha256` 绑定原计划。生成器只接收裁剪后的公开请求，不能把完整 Task 对象放入 prompt、工具返回或模型日志。私有材料应使用独立目录、权限或评估进程；“提示模型不要看答案”不构成隔离。公开 test 音频不等于公开 test 参考答案。

公共音乐工具预测和私有人工结构必须分开保存与标记。如果另外开放人工结构条件，单设 oracle-structure 赛道，所有 baseline 获得相同输入；不能只给新方法。盲评包不包含模型别名、实验假设或私有目标答案；评审可看到完成判断所需的原曲、计划、编辑指令及保护条件。

## 4. 歌曲分组、来源与泄漏审计

先分组、划分原曲，再切窗、产生候选和编辑任务。`song_group_id`、`artist_group_id`、`near_duplicate_group_id` 缺失时保留 `null`；仅凭不同文件名、row ID 或音频SHA不能证明不同歌曲。未知分组只可做开发试跑，不满足正式发布准入。正式真实数据至少要求 `synthetic=false`、`grouping.status=reviewed`、全部分组ID非空且具有审计证据；修改状态标签本身不构成复核。

主赛道对上述组关系取连通分量并整体分配 train/dev/test，防止同曲切片、重编码、截取、变速、混音或同艺人泄漏。分组依据需有人工复核或可追溯证据，不能给每条记录随意生成唯一ID来绕过检测。完整歌曲和 `local5s` 片段共用原曲分组，任何 edit 派生任务继承其歌曲分组。若研究需要 seen-artist 辅助设置，应独立标明，不冒充严格主赛道。

记录音频授权/可分发范围、获取时间、原始文件与canonical文件哈希、来源关联、近重复检索及复核结论。源视频/编舞者或动作标注来源能识别时也应独立审计。精确SHA、声学指纹和相似度筛查提供不同证据，均不能单独担保无泄漏。对未知预训练数据污染，披露可检查范围与残余不确定性。

禁止用测试歌曲的窗口、参考编舞、人工评分、编辑答案或由它们生成的教师轨迹训练/搜索新版本。每次数据/分组修订生成新版本，重新绑定相关候选与评估。

## 5. 编辑合同与成功定义

v1 的 patch 绑定 `base_plan_sha256`，包含公开 instruction、allowed/repair IDs、protected 字段及逐字段替换操作；可替换路径以 CONTRACT 为准。`allowed_event_ids` 是目标区，`repair_event_ids` 是事先许可的衔接修复区；后者不是事后为越界修改补画的范围。其他事件与所有未授权字段保持。

`protected` 可保护整个字段、一个标量路径或所有事件的同名字段。编辑第二次副歌不默认传播到第一次副歌；全主题修改是另一个公开指令。原计划时间线、song/clock、motif引用与稳定ID仍需合法。

空 patch 可表示弃权，无操作也应保留并评估；它不能仅凭保持率成为成功。目标不存在、指代歧义、保护冲突等 case 应包括人工审查的合理弃权/澄清答案，不用模板替换假装理解自然语言。当前机器字段目标的 `eq/contains/gte/lte` 是字面检查，不能证明动作语义已经满足。语义目标未评审时记为 pending，不把它计为通过。

## 6. 分项指标与校准

| 层级 | 应报告 | 解释边界 |
|---|---|---|
| 软件/表示 | schema通过率、无效时间/引用、轨道冲突、时间覆盖、明确rest | 只检验可确定的格式与排程；核心程序不自动给音乐性或物理分数。 |
| 局部/整曲质量 | 音乐贴合、动作明确性、段落对比、主题回归/变奏、非预期复读、过渡的独立人评 | 不以唯一参考caption、ROUGE、词汇多样性或模型自报信心充当正确性。 |
| 编辑目标 | 每目标字面达成率、私有语义复核、全部目标同时达成率 | 无目标或未完成语义评审的任务不产生虚假的满分。 |
| 编辑保持 | 显式保护字段保持率、A∪R外变化、R内实际修改数/时长、多轮漂移、撤销 | 保护集合为空记NA；联合报告目标达成，防止no-op刷保持率。 |
| 联合编辑 | 所有必需目标、保护条件及有效性同时满足的任务比例；另列语义pending比例 | 只完成字面检查时必须标为 literal-only，不能命名为完整语义成功率。 |
| 可靠性/成本 | 已完成/失败/弃权、恢复、请求与token、墙钟、GPU与人工时间 | 失败算入原请求分母，记录全部重试；额外采样与评审不是免费。 |

新指标先做校准，暂不构造任意加权总分。将人工认可的不同但合理编舞、合理motif回归，与机械复读、静止、空计划、过度细碎动作、错误时钟、错配音乐、保护越界和无操作等对照一起送审。检查方向、排序、分数饱和、系统性误判和评审一致性；指标版本/阈值在正式测试前冻结。

音乐依赖检验需匹配时长、风格、近BPM等混淆因素，允许“都合理/无差异”。完整 no-audio 对照同时移除局部音频caption、拍点、结构和其他音乐语义，只保留统一任务要求与总时长；只去一路输入称该路径消融。换歌后文字改变仅证明敏感性，不能单独证明贴合。自动snap到拍点后的计划边界分数也不能证明人体动作同步。

人评随机化、盲化系统身份，分开评音乐契合、编舞结构、清晰度、可执行性与偏好；报告有效评审数、一致性及争议仲裁。以原曲组而非窗口或编辑条目为统计单位；多曲同组时先组内聚合再聚类bootstrap。软件的song-level bootstrap仅在每song对应独立原曲组时直接适用；新艺人泛化还应检查艺人聚类敏感性。

## 7. Baseline 与公平比较

最少保留：同一局部expert拼接；同输入/模型/预算的普通全局提示；全局结构与分层协调；受控编辑与普通全计划重写；同预算多采样/选择。强通用音频模型可作为独立baseline，但需明确其实际输入能力和数据身份。

同时报告模块消融与原生系统预算曲线。公平比较需对齐公开音乐信息、模型checkpoint/采样、候选与评审预算、最大输出、窗口策略、工具版本及重试策略；新增外层强LLM的收益不能全归于编舞机制。若能力或成本无法对齐，就分别报告，不伪装成受控消融。

模式 `concat/global/hierarchical` 只命名实现路径，不意味着已验证质量。`mock` 不能进入真实模型表；`replay` 必须追溯真实模型原始调用与完整身份，否则只能作回放夹具。没有微调checkpoint时应标 `native_base_only`，不称用户已训练模型。CPU fixture通过、模型可导入和服务器真实推理通过是三类验收。

实现已支持从一次局部采样导出不可覆盖的候选库，在三种方法间复用完全相同的音频观察和原始回答；私有评估不参与候选收集。复用不允许改变局部模型配置、窗口、seed或删除坏输出；首次采样与本轮新增规划调用分别计费/计数。分层方法新增按身体部位的边界文本历史和有界motif记忆，均为模型声明的计划信息，不能当人体真实状态或动作语义真值。

显式section/time/body选择器可生成并预览编辑目标，但任意自然语言指代定位仍属扩展任务。跨边界事件与跨身体范围事件不被自动扩大授权。paired compare命令按歌曲配对并按来源组bootstrap；缺失方法默认拒绝，交集分析须显式启用并披露遗漏，人工与模型评分不得混合。完全未提供的歌曲需另与manifest核对。

## 8. 三阶段发布门槛

| 阶段 | 可交付 | 升级前必须补齐 |
|---|---|---|
| Phase 1：pilot | 软件fixture；另采少量有权限的真实整曲试验，例如6首开发/6首留出，每曲5–10条编辑；真实调用、失败和标注成本报告 | 能复现时钟/来源/分组，隐私目标不进入生成，真实expert与外层模型分别验收，人工评审可区分好坏与no-op。小pilot不作领先结论。 |
| Phase 2：正式数据 | 冻结任务、分组、音频来源/授权、版本及private评估；根据pilot方差/效应与标注预算确定规模 | 正式样本量及分层覆盖依据、完整审计、冻结baseline与指标、歌曲级不确定性；不能把fixture或不相关5秒片段拼成整曲数据。 |
| Phase 3：leaderboard | 同版本任务的可审计提交、分项质量/成本与状态、明确更替规则 | 实际可运行的私有评估/提交隔离、提交频率规则与反复测试控制、异常处理、人工复核及维护责任；仓库尚未据此宣称已有公开服务。 |

最终测试仅在版本选择完成后使用；开发评估反馈与最终隐藏测试分开。Leaderboard本身是后续运营交付，不是添加一张CSV就已建立。若未来做 harness RSI，冻结的评估与数据隔离仍在可修改系统之外；更新权重不是本benchmark的必要条件。

## 9. 每次发布/提交的证据包

必须可追溯：数据版本与分组审计、音频原始/canonical身份、公开输入、代码与依赖版本、模型/processor/checkpoint身份、配置/seed/预算、原始请求与响应、规范化与失败记录、计划/patch哈希、字面诊断、独立语义/质量评审及实际成本。密钥不进入证据包。

本协议不编造尚未落地的CLI。服务器命令与参数以主README、实际 `--help` 和对应版本的实现为准；已计划但未接通的入口不能作为验收依据。


## 10. 当前协调harness实现与开发证据边界

coordinated 是新增可替换方法，不改变 local5s/fullsong/edit 三赛道和私有隔离定义。局部音频仍完整5.0625秒，原始Omni可附固定公开任务提示形成base-only零样本对照；双窗文字不能当真实动作起止。

全曲设计加逐块创作读取冻结候选、独立公共结构和已提交动作/主题文本历史。生成事件是新提案，引用输入只绑定来源，不证明音频语义、姿态、动作次数或物理可执行性。select-only仍是来源整包选择/逐字编译，二者单独命名和比较。

独立结构sidecar绑定原dataset bytes、原音频hash与时钟，不放宽旧候选身份匹配；只接受公开字段。谱变化结构算法的功能标签unknown、repeat_group=null，阈值未校准；不能将其称为人工结构或真正乐句。计量reviewed仍需作者真实核验，不从工具输出自动升级。

每块事件/token预算、服务端JSONschema能力和尾块合并版本必须冻结并报告；格式约束不代替语义/音乐评价。更少事件、更多主题ID、更高覆盖或不同文字均不是音乐质量改善。修订提示、结构或预算必须新运行目录，保留之前失败和全部费用；开发输出不得反复反馈为隐藏测试搜索。

2026-11-05三首真实开发验收仅证明实现/推理流程可运行；人评仍pending、正式分组/近重复未审、无独立测试或Leaderboard结论。CPU/mock、真实GPU与人评分项证据见VALIDATION_20261104.md；公开仓库不包含音频、原调用日志、私有评分或内网服务身份。
