# 多模型编舞基线与 agent 实验执行表

E2 多模型比较优先执行，E5 指标开发和校准随同推进；随后执行整曲生成、单轮编辑，多轮编辑作为推荐扩展。E1 数据标注质量实验后置。当前不新增训练，SFT captioner 可用后补跑同一份局部测试集。本文更新 [实验总方案](44_cvpr_experiment_matrix_20261110_zh.md) 的执行优先级、E2 模型范围与 harness 对照；[sol61 操作指南](48_sol61_baseline_evaluation_20261111_zh.md) 保留数据和现有 runner 的用法。

以下是运行前的实验规格与空白结果表，结果单元格全部留空；新增模型、agent 基线及指标并非都已接入。

H1 为 E3 整曲生成，H2/H3 为 E4 单轮/三轮编辑；此处 H3 是任务编号，不是 MiniMax-H3 视频模型。

## 3 H1 整曲生成主比较

### 3.1 任务、模型与数据

数据为 24 首 180–300 秒的完整歌曲，12 首 180–239 秒、12 首 240–300 秒；清单仍需准备。开发阶段优先复用已有三首开发歌曲，在原音频可用时验收预算；正式歌曲与开发歌曲分开。sol61 的 5 秒片段不能拼接替代完整歌曲。

固定局部专家为 `Qwen3-Omni-30B-A3B-Instruct`，外层统一 `Qwen3-VL-32B-Instruct`，不等待 SFT，也不根据 E2 测试胜者临时换专家。每个观察窗预生成 K=2 候选，公共音乐结构、候选与时间索引全部共享。公共证据可缓存复用，但不同方法沿自己的真实已提交历史推进。

| 方法 | 明确运行方式 | 本实验回答的问题 |
|---|---|---|
| 固定分层 workflow | 全曲大纲→按固定块顺序生成→固定结构检查；不使用测试评分反馈 | 单纯分层组织能达到什么水平 |
| Self-Refine 式 workflow | 相同任务下生成→同模型文字反馈→改写；开发集冻结轮数和停止规则 | 收益是否只是来自更多反馈与修改 |
| ReAct agent | 在共同工具集合中自主读取、生成、检查、修订与停止 | 通用 agent 能否完成任务 |
| 我们的 harness | 相同工具集合，使用编舞状态组织、有效约束跟踪、针对性局部修订与停止策略 | 领域控制策略能否在同等资源下改善编舞 |

24 首×4 方法＝96 份正式总谱。不是一次读完整候选后直接生成全曲的 global 对照。Self-Refine/ReAct 等均标为本任务 adaptation，不声称复现其原始 benchmark。

开发实现按以下执行顺序验收，正式运行前冻结完整模板：

1. 固定 workflow：读取公共证据→写分段大纲→按既定块顺序取候选和已有历史→写块→运行结构检查→按统一规则提交或记失败；没有自主重听、语义反馈改写循环。
2. Self-Refine：相同初始生成步骤→对当前块及相邻边界给出音乐对应、动作发展、约束与复读反馈→据反馈改写→检查并提交。开发起点为每块 1 轮反馈改写；是否停止由预先冻结的反馈协议决定。它可以使用相同证据读取能力，但工具顺序由程序预设。
3. ReAct：接收同一任务、工具说明、预算和可读状态→模型选择一个工具动作→返回真实工具观察→再次决策→提交或停止。允许它主动检索历史、检查并修改，也允许在预算内恢复失败；不强制采用我们的状态摘要模板。
4. 我们的 harness：同一工具循环，额外使用明确的已提交总谱、待解决问题、有效约束和证据索引组织决策；提出局部补丁、检查后提交，满足停止条件或预算耗尽时结束。记录每次接受/拒绝补丁的依据，不能只保留最终成功轨迹。

### 3.2 公平工具和预算合同

四种方法的程序可调用能力相同，区别在调度方式。计划统一的接口包括：读取音乐证据与候选、读取完整合法历史或区间、生成局部提案、检查结构/权限、修订并提交、结束。现有工具基础需要封装成同一接口；这些名称不是声称新增 CLI 已完成。

ReAct 不能被剥夺完整历史、公共约束或音乐证据；ours 的自动状态组织和摘要只是获取/组织信息的策略，其模型开销照计。所有方法均可早停。内部 checker 只返回预先公开的检查信息，最终评审及私有答案不进入生成过程。

开发预算起点如下，须在三首开发歌曲上统一验收后冻结。预算不是测试中按方法随意调整的参数。

| 资源 | H1 统一预算起点 |
|---|---|
| 共同候选 | 每完整观察窗 K=2；首次生成成本单列 |
| 外层调用数 | 每歌最多 `1 + 4U`，U 为冻结的规划块数；允许在块间分配 |
| 单次输出 | 大纲最多 4,096 tokens，其余最多 1,024 tokens |
| 单次上下文 | 同一服务与相同 65,536 token 上限；超限不得静默截断 |
| 总输入/输出 tokens | 从开发 pilot 确定统一上限，测试前写入合同；仅同调用数不等于同成本 |
| 额外音乐观察 | 每歌最多 `min(6, ceil(0.1W))` 次，W 为原观察窗数；同一局部专家、相同观察单位 |
| 超时 | 根据目标集群 pilot 冻结所有方法相同上限，保留超时结果 |
| 计费范围 | 大纲、反馈、总结、工具决策、修订、内部选择全部计入；最终独立评分另记 |

单独报告实际调用和 tokens，而不强迫每个方法用满预算。若额外音乐观察接口未完成，不只给 ours 开通；先在所有方法都可执行的同一合同下运行。

## 4 H2 单轮精准编辑

沿用 48 题：40 个需修改任务，动作替换、密度/力度调整、指定部位保持与修改、结尾/主题发展各 10 题；另有 4 个已满足和 4 个歧义/冲突控制任务。原稿从 H1 的 ReAct/harness 平衡选取、在编辑运行前冻结；同题各方法使用同一原稿。

对照为 No-op、ReAct、我们的 harness。两 agent 固定同一 Qwen3-VL-32B、公开目标/权限、可见历史及工具；开发起点为每题最多 6 次模型决策、每次输出 2,048 tokens，总输入预算和超时在开发集冻结。当前只允许明确事件范围内修改 action 正文，不增加事件、不重排时间、不声称任意自由指代已完成。

## 5 H3 三轮连续编辑（推荐扩展）

这是新增的小规模任务扩展，验证 agent 的持续状态管理，不是新增训练或机制消融。参考 ClawMark 的状态变化和 τ-bench 的终局核验。优先完成 E2/H1/H2，H3 不阻塞核心主表；若论文主张多轮编辑能力，则需要完成它或收窄该主张。

选 12 个场景，每场景使用同一初稿、预先固定 3 个用户轮次。ReAct 与 harness 各运行一次，共 24 个会话、72 个用户轮次：

| 用户轮次 | 指令设计 | 核验重点 |
|---|---|---|
| 第 1 轮 | 指定局部动作修改，并明确保护条件 | 完成目标、保护原稿 |
| 第 2 轮 | 新增或收紧一个兼容要求 | 新要求完成，仍有效的旧条件保留 |
| 第 3 轮 | 修改或撤销先前部分要求 | 正确更新有效约束，不盲目延续被撤销条件 |

使用稳定事件 ID 或公开时间范围，先不混入新的自由指代解析任务。每轮必须读取本方法上一轮真实提交稿；没有成功提交时保留 last committed state，同时记录该轮失败。不能用共同的理想稿替换错误历史后继续。

每个用户轮次采用与 H2 相同的预算起点。状态摘要、反思、工具选择均计费；不同方法接收相同用户指令，但真实编辑历史允许分叉。当前实现还需补对话驱动器、约束版本与终局库存。

| 方法 | 第 1 轮联合成功 ↑ | 第 2 轮联合成功 ↑ | 第 3 轮联合成功 ↑ | 三轮全部成功 ↑ | 终局有效约束满足比例 ↑ | 历史有效保护误改率 ↓ |
|---|---|---|---|---|---|---|
| ReAct agent |  |  |  |  |  |  |
| 我们的 harness |  |  |  |  |  |  |

三轮全部成功要求每轮都成功；终局有效约束满足比例只看最终仍有效条件，不能使用历史最高进度。被用户明确撤销的条件不继续放入终局分母。每轮成功、终局满足与整段会话可靠性分别报告。

## 6 保持选做的 agent 实验

| 选做项 | 固定设计 | 要回答的问题 |
|---|---|---|
| 预算曲线 | 预选 8 首，ReAct/harness 比较 0.5B、B、2B；严格匹配时复用 B | 改进是否仅依赖更多推理资源 |
| 重复运行可靠性 | 预选 12 个编辑任务，独立重置初始状态、3 个固定 seeds、2 agents | 平均成功率及三次全部成功比例是否稳定 |
| Reflexion 式改进 | 跨完整尝试保留文字反思，只使用公共工具反馈，尝试全部计费 | 跨尝试记忆是否改善结果 |
| 一个机制消融 | 在历史组织、重听、局部修订中选一项，保持工具与预算可比 | 哪个机制贡献收益 |

三次全部成功比例是可靠性测量，不是 best-of-three 的 pass@3；同一对话的三轮也不是三次独立运行。以上均不作为 E2/H1/H2/H3 的完成条件。

## 7 E5 与执行次序

E5 随 E2 推进：固定来源的人评相关性、合理改写/主题复现/动作关系错误/保护违反控制样例、unknown/协议失败分母都保留。自动语义检查的引用合法不代表语义正确，现有受控事实 judge 的错误记录不得作为已验证指标成果。更多模型使裁判偏差检查更重要，不以单一自动分数直接宣称 SFT 最优。

另外补一项音频反事实检查，验证音乐适配指标是否实际依赖音频：预选 12 个测试来源，每源固定一段 E2 编舞文本，按六个公开模型各 2 例平衡分配，不按输出质量挑选。每段文本分别配原音乐、节奏/能量明显不同的同长度音乐、节奏/能量接近的同长度音乐，使用已有 WAV，不重新生成编舞。形成 36 个评分对象与 24 对比较；两个替换条件不能预设为更差或等价，须由两名评审独立听音确认实际差异、平局或 unknown。

替换规则在开发数据上冻结；正式 12 来源仅用于验证。音频 judge 对 36 个对象匿名独立评分，比较它与人工的配对排序、合理替换误罚及未知比例，按来源计算区间。固定文本避免文字变化解释分差。该项验证裁判；O2 则检查生成模型的音乐条件敏感性，符合合同的素材和评分可复用。没有音频敏感性证据时，不将自动音乐分作为已验证的主质量结论。

| 音频 judge | 与人工配对排序一致率 ↑ | 人工确认合理替换的误罚率 ↓ | 有效判断覆盖率 ↑ | 未决比例 ↓ |
|---|---|---|---|---|
| Qwen3-Omni-Thinking（拟用，待验证） |  |  |  |  |

评分差的平局/明显下降阈值只在开发集冻结，控制测试不调阈值。E2 的裁判与人评偏差另按生成模型分别汇总，避免总体相关性掩盖某一模型家族的系统偏好。

统计按来源配对：E2 按已声明的视频来源组，H1/H2/H3 按歌曲聚合后 bootstrap 95% 区间；对话轮次、同歌多题和两名评审不作为新增独立歌曲。E2 若检验 SFT 相对六个基线的显著性，预先指定主维度并校正这六次比较；其余维度报告分差和区间，不从大量切片中选择显著结果。

| 执行顺序 | 本轮具体交付 | 运行条件 |
|---|---|---|
| P0-1 | 六模型统一音频＋prompt 协议与原生适配；先验收 Omni/MOSS-Music/Music-Flamingo，再补其余 | 12 条开发音频；目标集群推理 |
| P0-2 | 96 条×6 模型的固定原始输出及失败/成本；并行补参考指标、独立音频 judge 与 E5 | 不依赖 SFT |
| P1-1 | 同工具的四种整曲方法、冻结预算、24 首×4 条件 | 完整歌曲；新循环基线接入 |
| P1-2 | 48 单轮任务；正式语义评审、目标与保护库存 | 复用 H1 原稿与已有 edit_agent 基础 |
| 推荐扩展 | 12 个三轮场景、有效约束版本与终局核验 | H1/H2 后执行；不阻塞核心主表 |
| 后补 | SFT 在相同 E2 清单上追加 96 输出；SFT 专家下的 harness 扩展另表 | 训练权重可用 |
| 后置 | E1 视频标注与 pipeline 对比 | 配套视频与视频评审器 |

目前 `coordinated` 是逐块生成并配合独立 bounded revision，不等于完整 ReAct 或 Self-Refine 基线；`edit_agent.py` 已有 generic/choreography 两种共享工具策略，但还不是上述全套多轮 benchmark。新增任务和指标需要接线与测试，不能因本表已经列出就声称已完成。
