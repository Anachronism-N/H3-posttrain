# 规划器 idea 的执行顺序与验收记录（2026-10-25）

本文件记录三个独立实验分支的下一步使用方式。范围是音乐到编舞文本的规划器，输出面向用户的舞种和带时间窗的连续动作文本。RSI 的评审与数据筛选只涉及规划器。

## 共同基线与证据边界

本轮同步的上游为 `experiments/music-planner-fair-20261025` 的 `4e22b8ef8016ee3bdfa85670a9d71aba7d277686`。三个 idea 分支通过 merge 保留上游历史，各自新增的实验代码继续独立维护。

上游的 `notes/33_music_planner_takeover_and_fair_eval_20261025.md` 和 `results/music_planner_v11_training_complete_20261025.json` 记录：清洗后 train 10713、val 490、test 500；三模型完成 2 epoch、670 更新、21426 次源曝光，各族内部验证选择均为 update 670。该记录来自上游已提交的服务器实验，本轮没有重新执行或远程复核这些训练。后续生成状态应按回执时间阅读，旧快照中的“尚未完成”不能覆盖新回执，也不能把训练预算完成等同于编舞质量通过。

上游还新增 MOSS 原生缓存解码兼容补丁和原生 EOS 缺失时的结束符补丁。实验生成入口须实际应用适用补丁，并记录源码身份、应用状态和原始 token。补丁处理推理兼容，不会把截断、重复或空动作自动修成合格 caption。

当前完整音乐窗口仍为 5.0625 秒，动作文本窗口为 `[0-2s]` 和 `[2-5.062s]`。这些分支未实现按小节动态训练窗口；改变窗口需要新的数据和输出协议，不能只改 prompt。严格音频长度门禁已随上游恢复，清洗数据排除的异常源不得通过填零或截断混入本轮实验。

## 第一阶段：用已有数据做候选搜索

先选定 train 侧小样本和独立 dev 样本，固定同一个模型 checkpoint 与每个候选的生成预算。开发阶段可先使用每源 4 个候选。保存全部候选，包括重复和失败输出；不能只保留好看的案例。

评审者得到原音频、候选文字与冻结 rubric；候选顺序打乱，模型身份、采样次序及已有评分由内部映射保存。即使隐藏元数据，文字和音频文件名仍可能暴露线索，所以这是有限的盲评。评审内容应包括音乐适配、舞种兼容、动作衔接，保留不确定、并列和不批准。

固定第一个随机候选可以作为单次采样对照，但它不是公平实验的 greedy 对照。若需要对比原 greedy，须另外保存同源、同 checkpoint、同生成预算的 greedy 结果并单独评审。

用于挑选候选的分数再用于报告，会产生选择偏差。该报告只描述这批候选的筛选行为；判断可迁移的收益需在新 dev 音乐和独立评审中验证。报告同时列出总源数、实际可配对源数、未选中/并列/不确定数及成本，不能仅在少数获批源上报告平均分。

分组关系未知时可生成和评审。训练导出仍需核验 source/song/near-duplicate 隔离；通过格式检查和人工声明不等于已完成歌曲去重。生成计划保留独立伪标签 schema，不回填成原视频观察真值。

## 第二阶段：舞种决策与保守条件生成

现有公平动作数据没有明确舞种标签，需要先定义舞种词表并补独立标签。音乐曲风与舞种不是同一字段。一段音乐可以有多种合理编舞：软标签表示当前互斥选择空间的分布，不等价于多标签任务。

train 用于训练分类头、val 用于模型选择、cal 用于拟合温度；按歌曲和近重复分组划分。分类头的 softmax 概率经过温度拟合后仍需检验可靠性，不能直接当作真实正确率。

生成时记录 top-k、最高概率和前两名差距。阈值在开发数据确定并冻结；低置信时回退到原生动作生成，保留预测分布而不强加舞种。评估须同时报告条件覆盖率和错误率，避免通过大量回退制造“准确率提高”。按手势舞等类别单独检查，防止稀有类别总被回退。

先比较原生生成与有条件生成；分类头准确并不自动证明动作遵循舞种。当前完整条件 SFT 尚需另行实现和验证，现有条件 collate 接线不构成真实模型已学会风格条件的证据。

## 第三阶段：短计划与直接 caption 消融

两个模式使用同一批经过审核的训练与验证来源、同一模型初始化、相同 epoch 与源曝光。直接模式只监督最终动作文本；短计划模式监督音乐证据、计划和最终动作。审核中间标注不会自动升级原 MotionScript 弱标签的语义质量。

短计划会消耗更多训练和生成 token。实验同时报告源曝光、监督 token 数和实际生成 token；相同样本数不等于相同计算量。可分别比较相同源曝光和相同总生成 token 上限；后者会压缩短计划模式留给最终 caption 的预算，应明确记录。

短计划中间段不能作为实际音乐理解的自我证明。最终比较使用音乐证据正确性、动作具体性、跨窗衔接、手势信息和独立人工偏好；token NLL 只用于同族内部检查点选择，不用于跨 tokenizer 排名。

不同实验模式使用独立 run 目录和 checkpoint。源码与数据身份改变后不要硬续旧断点；保留旧代码快照以复现历史结果。新推理补丁的应用记录应与训练身份分开保存。

本轮本地环境具备 PyTorch CPU，缺少真实预训练模型和服务器运行条件。CPU 回归可以验证梯度、恢复、路由、停止、数据隔离及评审绑定；不能作为真实模型质量验收。服务器首轮应依次检查原生完整音频输入、至少两个源的生成、有效 EOS 与完整动作窗，再执行两更新保存及新进程恢复 smoke，最后扩大实验。

达到“方案有效”至少需要：协议冻结、实际原生模型运行、完整原始结果和失败统计、独立音乐评审、可复现的数据/模型/代码身份。当前尚未实现在线 RL、自动权重递归更新或额外音乐 encoder 融合；这些应在上述独立对照提供证据后再决定投入。
