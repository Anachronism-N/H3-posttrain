# 8a833c9 Review 与下一轮实验：先测音乐映射，再选择训练改动

日期：2026-11-09。审查提交 `8a833c94f1934d963647580025b63195a50527cb`；该提交修改README和[报告34](34_music_caption_analysis_20261109_zh.md)，没有加入其提议的诊断/新训练实现。本轮在 `codex/music-choreo-benchmark` 新增独立 `captionlab`，不启动训练、不改冻结ChoreoBench。

本文只覆盖Captioner线；与harness的并行实验、独立验收及后续联动见[双线执行安排36](36_harness_captioner_parallel_experiments_20261109_zh.md)。音乐可以对应多种合理编舞，参考事件/侧别/次数匹配用于记忆或参考一致性诊断，不作为一般生成质量的唯一真值。

## 1. 新证据改变了什么

报告中的全量标准SFT与EOS20，各193,278训练样本、6,040更新、约51.6小时/8×A800，属于**新的一组运行记录**。不得与此前main文档里的196,097样本、5515检查点拼成同一条学习曲线。其原始checkpoint、音频、18条生成与日志未在本机获得，本轮核查的是报告、仓库接口和可复现的软件行为，不能声称重跑了这些模型。

| 观察 | 可以支持 | 尚不能支持 |
|---|---|---|
| 三例标准SFT真/错配NLL差由约0.005885降至0.002642；最终2/3错配略低 | 下一轮必须测具体音乐条件信息，不能只看CE | 三例证明模型完全不听音乐，或估计总体效果 |
| greedy存在12子句块完整重复19次、达到2048上限 | 存在次数膨胀与停止/推进问题 | 闭集词汇本身错误，所有重复动作都应删除 |
| EOS20 greedy三例均未完整；采样可结束 | 加EOS权重不是已证实修复方案 | 仅修采样即可证明动作与音乐对应正确 |
| 无额外匹配目标，原音频末4层LoRA | 可以设计目标负担与音频scope因素对照 | 必须先加RL/DPO、全解冻或更大rank |
| JEV本轮未启用 | 后续可把舞种从文本生成拆出 | 已有新的JEV分类结果，或unknown文本失败等于JEV失败 |

当前最有价值的下一步是**冻结现有检查点的诊断**。首轮训练2×2方案保留，但在实现正确性、固定验证清单与错配证据没有就绪前，不再做一次193k全量。

## 2. 本轮落实的代码

| 文件 | 实际能力 | 明确边界 |
|---|---|---|
| `captionlab/targets.py` | 原caption保留；显式舞种/JEV标签分离；保留/去数字时间戳；完整窗裁剪清单与split审计 | 不改动作、不猜侧别、不训练JEV、不实际裁音频 |
| `captionlab/manifest.py` | 固定val IDs；来源/同歌/近重复/文件/PCM排除；同几何候选；缺失条件保留 | 困难候选由外部冻结；不从BPM推定语义负例 |
| `captionlab/runtime.py` | 原collate的连续assistant后缀逐token因果NLL；分块FP32；eval/no_grad/no-cache | 不通用实现KV parity，不加载未知合同，不产生action mask |
| `captionlab/runner.py` | 显式原runtime factory与artifact SHA；音频快照；同几何静音；逐条日志、失败分母 | 实际训练快照factory与portable核验仍由服务器原环境提供；声明文件列表完备性不能自动证明 |
| `captionlab/scoring.py` | 同y/同token/同EOS支持检查；wrong−true差；组等权与cluster CI；并列/缺失/已审subset | 不把teacher forcing当生成质量；未知动作mask为NA |
| `captionlab/__main__.py` | prepare / targets / run / summarize | 无训练、模型下载、生成或自动resume命令 |

此前 ChoreoBench `NativeProvider` 只接其固定fair/direct协议，源码SHA还要匹配训练时版本。报告34来自main及未同步扩展；不能靠改checkpoint路径就宣称完成新模型接入。新的独立工具要求经原factory构造adapter，`collate`保留原分段token约定，不用旧分词方式重建所有目标。

运行前冻结：原检查点/基座完整身份、训练runtime及processor、目标合同、256项原验证ID、pair表、seed、解码和评分模式、所有排除/未知原因。原始音频与caption不覆盖。来源组和PCM是输入元数据声明，尚未完成的歌曲级非精确重复审计不隐去。

## 3. 接下来按这个顺序执行

### E0：只做运行与实现核验，先3例

1. 在原服务器找到两组6040 checkpoint及官方初始化、对应run_config/代码快照/完整portable清单。不要先合并不同branch的loader。注册原factory，核验可训张量实际恢复与原目标分词/原生EOS；基座与SFT的评分前缀协议一致。
2. 导出原三例的完整来源字段、原caption与明确时间窗；补正确/随机候选/显式困难候选/静音清单。确实没有困难候选时保留缺项。本工具开发probe只接受val；先核实三例所属split，若不是val，不得改标签迁入，应保留原诊断工具另记该三例，并为本probe冻结三条val冒烟案例。
3. 最多3例×4条件×3检查点=36次teacher-forced前向，无新生成、无训练。核验target IDs、EOS、有效支持、实际音频SHA、同几何、零波形重新处理及有限NLL。单例失败停下，失败记录保留，不以重试后成功覆盖。
4. **另一个尚未实现的服务器核验**：同一预定目标序列下cache/no-cache next-token logits与ZeRO/portable前向对照。不能比较自由生成已分叉的文字；记录max/mean logit差、目标logp、top1和margin，阈值由实际dtype/基线校准。当前评分使用no-cache，但生成质量诊断前仍需要这个门槛。

E0只判测量可信与否，不判模型胜负。三例来自原开发例，不当新测试集。

### E1：固定256验证来源，先不训练

每个检查点最多256×4=1024次teacher-forced前向；标准SFT、EOS20、官方初始化顺序运行最多3072次。可以先完成标准SFT的E0，再逐个开启其余profile；不同时占三份30B模型。清单中缺候选则减少实际调用，但总任务/缺失数仍报告。代码的`forward_calls_per_checkpoint`是可执行数，不是推测耗时。

共同目标为原始raw caption，各条件仅换音频；先报告全有效assistant（含EOS）NLL。动作信息token子集要用核验过的span/token映射另行导出mask，保留无法判定的unknown，**本轮尚未完成自动动作parser和native offset对齐**。仅去掉目标文字再评分会改变teacher-forced上下文，不能替代mask对照。

必须保存：

- 每case/每条件NLL与wrong−true差；random/hard/silence分开，不把静音收益冒称辨别具体音乐。
- 预登记、实际完成、缺候选、推理失败、有效支持与来源组件数；已审hard subset的并列排名和完整分母。
- 按来源组件重采样的区间；单组件NA。区间条件于固定donor集合；复用donor和未知同歌可能导致剩余相关性，不能作为严格总体独立检验。
- 原三例完整生成的动作部位/方向/侧别/顺序/并发/次数、EOS/预算截断、真实循环证据。现有原始结果优先审阅，无须为画更多图先重跑生成。

判定：对hard只见零附近/不稳定差值，说明“这个已审subset没有显示可靠映射优势”，不能宣布音乐与编舞不可学习。音频swap敏感、比静音低loss、BLEU/复用率变化均不是单独通过标准。若诊断本身无法加载/复现原目标，先修实现，不升级训练。

### E2：先准备保事实目标，训练仍暂缓

`targets`已经能输出两份相同动作事实的数据合同：舞种拆给JEV的带时间戳版，以及进一步去数字时间戳版。raw、权威时间、字节spans、unknown和上下文依赖保留，闭集动作与真实重复不删。

准备好并通过新合同前反向/保存恢复/单case→8case有界记忆验证之后，再执行报告34的2×2：

| 配置 | 时间戳目标 | 音频LoRA层 | rank | JEV |
|---|---|---:|---:|---|
| P0 | 保留 | 末4 | 32 | 同一known-label协议与权重 |
| P1 | 去数字标记 | 末4 | 32 | 同P0 |
| P2 | 保留 | 末16 | 32 | 同P0 |
| P3 | 去数字标记 | 末16 | 32 | 同P0 |

固定2k–5k原来源、split、初始化、全局batch、曝光/更新预算、监控点；无EOS额外权重、无禁重复动作词。JEV分类权重0.1只能作为预注册起点，不是已验证最优；若要证明JEV本身的增益，另加同协议lambda=0对照，不能从这四组得出JEV收益。未知标签mask，不把音乐genre代替舞种。

本轮**没有把转换文件直接接进main训练器、没有新增训练开关**。新合同需要trainer读取转换版本、JEV prefix取位/标签mask与独立分母、adapter+JEV完整export/restore测试；这是下一阶段明确剩余工作。P0–P3不能混用原timestamp门槛评价P1/P3。

### E3：只有前面的证据支持才扩展

音频scope有效后单独比较rank32/64，不把层数和rank同时改成一个因素。已有完整1–3秒窗裁剪可作为后续独立对照：代码现在给计划，真实裁剪/PCM核验、历史pad交集、上下文依赖准入和按原来源秒数/事件数匹配曝光仍待执行。全5秒与局部窗不能监督同一份5秒全文。

只有映射诊断仍弱、实现可靠并有经核实负例时，才比较CE+JEV与小权重条件ranking；先每样本至多一个负音频，承认额外前向/反向成本。更多词汇、去重复或更长caption不作奖励捷径。当前不实现DPO/RL替代这些验证。

报告34记录单卡加载约61GiB，因此80GB只是首选候选，不是所有最长目标必然可跑的承诺。建议按该报告推理节点约140GiB可用CPU内存、80–100GiB本地空间作为准备参考，先跑最长目标与3例测peak；实际以环境准入为准。每次首次审计完整权重SHA会产生磁盘读取成本。

256个24kHz、5.0625秒、float32单声道音频，波形数据约0.124GB（十进制），音频快照及静音副本另占空间；若donor来自更多源、原容器更大应按实际文件和选择清单估算。日志含逐token NLL与目标，保持私有数据目录，不推到GitHub。模型/音频/凭据不会随代码提交。

本轮本机验证：`python -m pytest -c captionlab/pytest.ini -q`，**162项通过**（含真实tiny CPU Torch前向、35项子测试；不是30B推理）。使用独立既有CPU环境，没有改共享依赖。测试覆盖raw/Unicode/重复保真、跨split/多正例排除、同几何、静音快照、因果shift/EOS、失败分母、源文件与旧pyc错绑、重复/缺失token记录和统计边界。新增独立Linux/Windows×Python3.10/3.12 CI；远端状态以本轮提交的Actions记录为准。

无Torch的Python3.9环境并关闭UTF-8模式，准备/汇总测试119项通过、2项跳过（Torch模块/端到端模型测试）；ChoreoBench回归933项通过、4项按原条件跳过。未修改其生成、评分或原NativeProvider代码。最终接口复核还补齐了main configured adapter必需的`audio_duration_seconds`和原窗caption metadata，并加入联调断言；这不等于真实6040运行环境已经验收。
