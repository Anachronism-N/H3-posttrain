# HereWeChoreography：独立严格审稿

审阅日期：2026-11-17。审阅版本：`cf34d63980d5b15190fe90076cc8a4c3e705ae34`。范围：16 页论文、8 页正文、主表与冻结结果来源。以下是内部模拟审稿，不代表 CVPR 官方评分或录用预测。未启动训练、生成或新的质量评测，也未修改论文。

文件定位均相对于 `paper/HereWeChoreography/`；行号指本版本的 TeX 或冻结工件。本文区分“已经观察到的问题”“缺少验证”和“审稿判断”，不把缺证误写成已证伪。

## 总体判断

**按当前可核验的完成证据，我倾向拒稿，主要原因是核心贡献与验证对象没有闭合。** 这个判断并非来自表格数量或图不够精美：最新主方法尚无对应的端到端结果，已完成的质量主表不能隔离训练模型与额外编辑器，新的 benchmark 评分仍缺独立校准，数据贡献也缺原始视频到最终文本的质量审计。

方向具有价值。文字总谱把动作、时序、复现和编辑变为可检查对象；音乐到文本编舞也确实值得建立资源和评测。然而，当前稿件更接近“有局部实验证据的系统方案与评测设计”，尚未形成“四项贡献均已验证”的研究论文。只删除局限说明或换更强的命名不会补上证据。

### 已经成立、应保留的证据

- 在已发布评测配置与参考文本上，任务 SFT 明显提高参考一致性。Table 2 的 30.80 ROUGE-L、89.71 BERTScore F1 等有冻结来源，不能把这点否定成“没有任何有效实验”。但它们衡量参考分布的复现，尚不等于音乐编舞质量。
- 已完成 822 个样本上的音频舞种伪标签分类比较；监督头在这个任务上优于所列零样本模型。应保持为“对视频 VLM 伪标签的预测”，不扩展为最佳舞种或编舞改进。
- 工程记录支持 controller 的交付和成本诊断，以及指定早期设置下的重复文字下降。它们支持可执行流程与软件控制的观察，不支持最新 harness 的整体音乐质量优势。
- 当前稿件已经正确保留全量主评测，未用结果筛出的 436 个优势案例替代总体；也未把 r4 与 v2.1 的每维最大值拼成新结果。这些改进值得保留。

## P0：决定是否能支撑主结论的问题

### R1．主图和方法不是当前长程实验实际验证的系统

**证据。** 正文 `sec/3_method.tex:25–63` 描述 SFT 专家、2–4 小节分窗、JEV、motif/history 与 bounded revision；`sec/4_experiments.tex:63–74` 则明确结果使用固定窗、无 JEV、声学证据访问不相等。冻结的 `results/harness/extension_set.json` 中 `collection` 明确是 frozen MOSS expert。`sec/9_method_implementation_details.tex:37–50` 还写明变长音频消费尚未完成服务器验证。对应正文第 2 页 Figure 1 与第 8 页 Table 5。

**审稿疑问。** 即使旧版本有效，也无法验证新模型、分窗和风格条件组合后的系统。不同组件分别在不同数据上有结果，不构成端到端组合有效性的证明；变长模型输入可能本身还不成立。

**最小补救。** 固定一份当前配置，让同一批未参与开发的完整歌曲通过 waveform → 实际模型消费 → 缓存候选 → 完整总谱，保存 trace。把使用当前 SFT 的 matched-evidence Workflow 与当前 harness 作为最小主要比较。对至少若干典型窗口长度确认没有静默截断、错位或伸缩。做不到时，必须将最新设计降为扩展，主要方法与结果围绕同一已执行配置写作。

**性质。** 当前“未验证”；不能据此断言新系统一定无效。

### R2．Table 3 的 Ours 混合了模型训练收益与巨大额外编辑器收益

**证据。** Table 3 将一行标作 Ours（`tables/refinement_d123.tex:13–21`），D1/D2/D3 为 4.97/3.33/4.80。`sec/8_supplementary.tex:53–64` 说明这是 SFT 后再经 Qwen3.5-397B-A17B 文本编辑；1,991 个最终文本不同于原始 SFT。Table 2 则评价编辑前模型，`sec/4_experiments.tex:7–12` 虽已说明阶段不同，但主表标题和主文数值仍容易被用于训练模型优势叙事。

**审稿疑问。** 改善可能来自额外模型、额外调用和措辞偏好。现有比较不能证明 SFT 本身 D1/D3 领先，也不能证明它比“基线加同样编辑器”更强。

**最小补救。** 在同一冻结 judge 上至少比较：原始 SFT、SFT + editor、一个强基线原文、该强基线 + 同一个 editor。报告额外模型与调用成本；分离“模型”和“完整流程”的命名。若只保留现表，应将其明确限定为预算不同的系统比较，不能承担模型独立质量结论。

**性质。** 混杂已存在；编辑器是否造成全部增益仍未知。

### R3．D1–D3 分数的评审协议无法充分复现，更不能验证新的 benchmark

**证据。** `sec/8_supplementary.tex:65–86` 说明公开导出缺 assessor identity、原始响应、引用证据和 acoustic metadata，baseline 缺 rubric 内容哈希。`results/d123_refine_v1/provenance.json:140–148` 也记录 judge identity 与锚点缺失；`sec/8_supplementary.tex:86–87` 明确旧记录不能证明九维锚点已校准。Table 3 却仍给出很接近满分的 D1/D3。

**审稿疑问。** “同叫 r4”并不证明是同一提示、同一 judge/checkpoint、同样上下文或同样失败处理。无法核对 4.97 的语义含义、是否奖励长文本、是否把显式术语当正确。现有格式验证不建立评分有效性。

**最小补救。** 公布或冻结可检查的评分 prompt、模型版本、参数、输入模态、音频消费合同、匿名化规则、原始回复与失败类型。选定一版量表，先校准再统一评价所有方法。只保留数值无法补救这个问题；若暂无法恢复协议，旧表只能作为历史自动评分而非 benchmark 验证主结果。

**性质。** 可复现性和效度缺证；没有据此认定评分造假。

### R4．尚未证明模型和总谱在利用音乐，而非复现标注语言的先验

**证据。** 数据是 text-only 的 2D 事件重写（`sec/2a_dataset.tex:14–21`）；主要数值是单参考文本重合（`sec/4_experiments.tex:17–29`）。音乐 D4–D6 在 Table 3 均为空；当前长程评审只看文字和声学摘要，不听原音频（`sec/4_experiments.tex:69–74`）。论文没有同分布错配音乐、音频条件移除或独立音乐相容性结果。

**审稿疑问。** 专用 SFT 可能主要学到了“手臂/手/膝及方向”的标注分布。它即使提高 ROUGE、KW-F1，也未必产生对输入音乐有辨识度的编舞。给同一音乐恢复某条参考动作既不充分，也不是本任务唯一合理答案。

**最小补救。** 在固定随机种子的独立素材上，加一个同分布错配音频控制，针对原音乐由独立听评者/已校准音频 judge 评价输出变化是否有依据。基线可用完全相同的现有模型，无需训练。评相容性和是否响应音乐差异，不强行认定同一音乐只能有一个动作答案；不要把原音频检索准确率直接当舞蹈质量。

**性质。** 音乐条件能力尚未充分证明；不是已证明模型忽略音频。

### R5．数据贡献缺少语义质量审计，而且主图重点路线不是现有标签来源

**证据。** `sec/2a_dataset.tex:14–21` 当前标签仅源自十六类 2D wrist/elbow/knee 规则事件；`:28–37` 明确 NLF/MotionScript 3D 路线尚未建立为当前 labels 的生产来源。Figure 2a 却把完整 3D 路线作为主要构造图（`figures/dataset_overview.tex:18–24`）。`sec/8_supplementary.tex:14–25` 的事件数、词数和部位占比是描述统计，不是 accuracy/coverage 增益。没有前后文本的视觉 grounding 人审结果。

**审稿疑问。** 220k 记录的数量并不能说明新资源比现有动作描述更准确、更丰富。重写可增加表达变化，无法凭空增加观测到的动作类别。精美的扩展路线也不能解释当前 SFT 数据的实际质量。

**最小补救。** 正文主图先忠实呈现当前 2D 生产路线，将 3D 作为扩展或在独立小样本上真正比较。抽取约 60–100 个来源分组样本，使用原视频与事件记录检查动作存在、部位/方向、先后、遗漏和新增无依据内容；比较原规则描述与最终 caption。两名评审独立给判断，公开抽样和分歧处理。无须重标全库，但必须有质量估计，不能只报告检查器通过率。

**性质。** 主图与核心数据贡献存在重点错位；作者已在 caption 诚实披露，不能将其称为蓄意误导。

### R6．测试集声明没有完成与实际训练运行的闭环

**证据。** `results/e2_full2000_protocol_and_selection.source.md:36–42` 记录预先冻结且排除了声明 train/val ID、来源组和音频哈希；同时明确来源组不是认证独立歌曲。`sec/8_supplementary.tex:140–149` 承认需要真实训练/checkpoint 清单和 provenance 审计。正文只给窗口记录划分（`sec/2a_dataset.tex:7–11`）。

**审稿疑问。** 同一歌曲可出现在多个视频、不同裁剪、变速、压缩或混音中，字节哈希和视频来源 ID 不充分。元数据 train/test 没交集，也不能替代实际 run 训练清单。窗口级数量尤其容易制造大量相关样本。

**最小补救。** 冻结实际训练记录清单、checkpoint 与数据版本；核对视频组和规范化音频指纹/歌曲级重复，报告可认证去重范围。必要时在歌曲/来源级留出重跑已有推理。无法完全识别歌曲时清楚限定泛化主张，不把未知项视为 clean。已有冻结和排重是正向证据，不能无依据宣称泄漏已经发生。

**性质。** 泄漏风险未排除，不是发现泄漏事实。

## P1：会显著削弱论文说服力的问题

### R7．长程质量优势被证据访问、评审家族和开发复用混杂

证据：`sec/4_experiments.tex:63–81` 承认不等声学证据、Qwen 同家族、四曲开发复用；独立 MOSS 检查为 +0.50 [-1.00, 2.00]。`results/harness/formal_result_v1.json` 的独立 test 子集只有两首，效应 +0.25 [-3.5, 4.0]；原始合并结果包含开发曲。extension 有八个有效对但只来自 Electronic、180–280s（`extension_set.json`）。

需要：固定候选、声学证据、风格、主模型、输出上限与失败/重试政策；先完成 Workflow、Self-Refine、ReAct、当前方法的统一比较。最关键补充是 independent audio+text 人评，不是再加一个同家族 judge。开发曲可保留机制分析但不承担独立总体结论。不能把 MOSS 的不确定结果写成“否定优势”，也不能忽略它只保留 Qwen 的正结果。

### R8．rubric 是有待验证的设计，尚非经验证的指标贡献

证据：`sec/3a_evaluation.tex:29–41,64–70` 和 `sec/8_supplementary.tex:151–153,255–263` 明确 calibration、listeners 和 human agreement 尚未完成；旧 D6 只适用于有明显局部变化的短片段。新情绪 D6 目前只在 notes 中，不是该论文已完成协议。

需要：在开发集验证改变后来性/顺序、只加修饰词、重复换同义词、音乐错配、合理半速和 motif return 等控制。冻结维度后，用独立样本测 ordinal agreement、成对方法偏好一致性及可用覆盖；报告 Unknown/失败。检查 D4/D5/D6 是否提供不同信息，不按我们是否领先选 rubric。不能把漂亮的 1–5 锚点表当成有效性证明。

### R9．文本可执行、音乐契合和真实舞蹈可执行是不同的结果

证据：`sec/3_method.tex:56–57` 的检查仅事件 bounds、tracks、motifs；`sec/9_method_implementation_details.tex:62–71` 编辑只验证 scope/transaction。Figure 3 是人工撰写说明（`figures/choreography_example.tex:10–12`），没有实际模型—视频执行结果。

需要：保留“written-plan compatibility”的准确边界。至少提供真实模型输出与人工可读性/排练可理解性评估，加入成功与失败案例。**不要求为文字任务重训 H3，也不要求强行使用 FID/MPJPE**；但不能把事件时序合法、描写看似详细或作者编写的图例升级为 physical feasibility、真实同步或模型执行证据。

### R10．需要更清楚的任务差异和近邻工作讨论

M³GPT 已有 A2T 任务；DanceChat 已使用音乐描述产生文字舞蹈指令；AtomicDance 已做原子动作类型/时间规划；ChoreoStudio 已显式分离编舞计划与动作实现。当前 Related Work 仅简单提 M³GPT/DanceChat，未讨论后两者，见 `sec/2_related_work.tex:4–15`。

这不否定本任务价值；真正可争取的区别是“开放词汇文字总谱作为终端对象、长程工具控制与编辑、可复用证据资源、音乐+文本的分层评测”。需要一张小型任务接口比较，清楚写输入、输出、时间跨度、是否评文字本身。无需把不同输出形式的方法硬塞入同一数值表，也不要不加核查地声称“首个音乐到文本编舞”。

一手来源：

- [M³GPT，NeurIPS 2024，附录 Table 15](https://proceedings.neurips.cc/paper_files/paper/2024/file/316648eb8b4ffb6010f531b07848c300-Paper-Conference.pdf)。
- [DanceChat，arXiv v2](https://arxiv.org/html/2506.10574v2)。
- [Music-to-Dance Generation via Atomic Movements](https://arxiv.org/abs/2607.13978)。
- [ChoreoStudio](https://arxiv.org/abs/2610.32325)。

只核实以上作品公开内容，不据此声称 2026 年两篇预印本已中稿顶会。

### R11．关节加权属于合理训练配方，目前不能承担主要算法新颖性

证据：`sec/3_method.tex:8–23` 与 `results/joint_clause_weighting/` 现在正确表示 weighted CE，实际只对腿部相关从句使用 1.5。`sec/8_supplementary.tex:155–166` 说明 offset fallback 与随机从句对照缺失。

“Joint-aware clause reweighting”是可以接受的上位描述，但不能暗示独立学习的逐关节坐标权重或更丰富的运动空间。若不再训练，保留为实现选择即可；只有要主张其因果贡献时，才必须补 standard CE、随机等量从句加权和目标从句加权的同条件消融。不能把 v1→v3 的所有差异归给这一因素。没有必要为此再训练多个基座。

### R12．JEV 分类比较不能替代全局风格条件的效用验证

证据：Table 4 是监督 MuQ 头与零样本模型预测 video-VLM 伪标签；`sec/8_supplementary.tex:106–123` 说明 22 输出中只观察 13 类，其中五类仅有 1/1/1/3/16 个测试样本，训练正例覆盖 15 类。`sec/3_method.tex:39` 未解释 JEV 全称/接口意义。

需要：对外明确 JEV 是全局舞种先验模块及其实际 MuQ+classifier 实现，保留监督制度差异。最小下游试验是同一总谱生成系统关闭风格、使用预测风格、使用人工给定风格，并检查 body-action text 与音乐适配。没有该试验时只能说“能预测伪标签”，不能说“改善编舞”或“发现正确舞种”。稀有类别的 Macro-F1 可描述报告，但不能拿作稳定跨文化泛化结论。

### R13．主要结果缺少对应的不确定性，完成率和质量也不能只看成功子集

Table 3 的 D3 优势仅 4.80 vs 4.63，既没有配对区间，也没有人类可辨识意义校准。Table 5 的质量只在双方成功歌曲上报告；虽然 completion 已列出，但 paired sample 是条件子集。四曲 bootstrap 的窄区间不意味着代表性强。

需要：优先恢复 source/song mapping，按歌曲或来源组计算配对区间；无法恢复时明示仅 case-level 描述，不能假设窗口独立。对所有 registered songs 同时报告交付率、成本和成功交集质量，不把错误/Unknown 随意填 0，也不将不同方法的可用均值直接相减。固定推理预算与输出长度；评审也需检验 verbosity/position 敏感性。

### R14．目前没有真实输出的长程 case study

现有四张主图分别是方法、几何扩展、作者编写例图和未校准协议。Figure 3 可解释 schema，却不能证明模型真的生成了高质量编舞。重复字符串下降也无法说明动作变化或 motif 合理性。

需要：用预先声明的选样规则加入至少一首完整歌曲的真实总谱缩略时间线，显示其音乐证据、局部专家原文、选定改写、被保护上下文和失败位置；再补一个方法不如基线的案例。只展示可公开的真实冻结输出，不将说明性例文标作模型输出，不只从 436 个优势案例筛选成功故事。

## P2：写作、图表和可复现性改进

1. **研究结论被进度说明割裂。** 当前频繁出现 prospective、unverified、pending、historical 等词，是实际缺实验的表现。正确办法是补核心验证或缩小主张，不是把这些必要限定全部删掉。主文每段应围绕一个已完成论点、一个实验和一个明确结论。
2. **正文页面分配偏离完成证据。** 第 3 页的 3D 扩展、 第 6 页的待校准量表占据大量空间；主要结果集中在第 7–8 页。优先给当前生产数据流程、可验证的真实输出与公平主实验让位，细节放可检索附录。
3. **表中视觉重心。** Table 3 三列全空容易把“缺核心验证”变成阅读焦点。正式提交时优先补齐；若做不到，表只报告已评维度，音乐评测设计另表清楚标注未完成。无需重复打印每个分母，但完整协议和范围必须能查。
4. **模型版本与停止条件。** `sec/8_supplementary.tex:94–103` 说明基线 stopping metadata 不足。列出模型 revision、统一任务提示、音频完整消费、max tokens 和终止原因。若现有 Qwen3-Omni-Instruct 确为相同底座，补 revision 证据即可；否则加 adapter-off 推理对照，无需训练。
5. **成本需要覆盖整个系统。** 本地专家、声学分析、JEV、composer 与 397B editor 分开记账。报告冷/热启动、调用、输入/输出 token、实际 wall time 和失败。`1+4U` 是调用上界，不能证明 token 成本随歌曲长度线性；完整历史可能增加上下文成本。
6. **数据卡与发布范围。** 需要数据来源、源视频/歌曲数量与时长范围、划分单位、事件 ontology、过滤规则、可公开样例、数据生成模型版本以及媒体许可范围。derived caption 的可见性不能替代原媒体可再分发许可；这属于发布可复现性要求，不作法律判断。

## 最优先、无需新训练的修复顺序

| 顺序 | 工作 | 可以回答的核心质疑 |
|---|---|---|
| 1 | 冻结唯一方法配置、训练清单、评测注册清单、grader prompt/模型/日志 | 结果究竟属于哪套系统，能否复现，训练测试是否闭环 |
| 2 | 以当前 SFT 为共同专家，跑相同候选/音乐证据/预算的 Workflow 与 harness；随后补 Self-Refine/ReAct | harness 是否优于同条件的简单流程，而不是只多拿了证据 |
| 3 | 两名评审完成独立音频+文字对比；冻结后统一跑音频 judge | 整曲音乐编排是否更好、模型评分是否可信 |
| 4 | 原始 SFT、SFT+editor、强基线、强基线+同 editor 的对照 | 模型收益与额外编辑收益如何区分 |
| 5 | 视觉抽检源事件/原 caption/最终 caption，补短视频证据与失败类型 | 数据质量、改写保真、闭集事件扩展的真实边界 |
| 6 | 配对音频错配、只加形容词、合法 motif return 等控制；补真实总谱 case study | 是否真正用音乐；评分能否识别实质变化 |

若只有 1–2 天，优先减少主张和实验分支，把 1–3 做成可核验的最小闭环；4–6 可以缩小开发规模，但不能用未运行的计划替代结果。不要为了凑四个贡献而增加未验证模块。**不建议把剩余时间优先用于继续换图名、堆更多自动评分版本、训练其他基座或训练 H3。**
