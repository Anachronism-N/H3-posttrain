## 2. 97% 具体意味着什么

上游报告交付220,667条，包含198,315条train和22,352条val/test。其分层统计针对 **198,315条train**：

| 规则层级 | 报告数量 | 重算占比 |
|---|---:|---:|
| A_narrative | 264 | 0.133% |
| B_partly_rewritten | 5,755 | 2.902% |
| C_raw_template | 192,296 | 96.965% |
| A＋B | 6,019 | 3.035% |

数量相加一致。“97%”是该启发式规则的 C 层比例，不是独立视频核验的错误率，也不是全220,667条的质量统计。本机已核验规则和算术；未取得完整原始输出与分层产物，Hugging Face 页面访问及API连接未成功，未独立重算总体比例。

报告中的大量逐关节模板句仍是重要开发证据：它说明大规模生产覆盖与语言组织不是一回事。但应同时保留两个边界：关节词/合法舞步重复本身可以正确；叙事流畅也可能遗漏、混淆或新增错误动作。

## 3. 分层脚本的可复现问题

本轮直接读取 `ce4fc96` 中的原脚本，在临时合成 JSONL 上运行，未改原脚本、未启动模型。以下是实际结果，不代表真实数据中这些异常的发生率。

| 合成输入 | 原脚本结果 | 暴露的问题 |
|---|---|---|
| 空字符串 | A_narrative | 无有效内容门；默认分支把空输出当最高层 |
| 只有 `Dance style: contemporary` 或空时间窗 | A_narrative | 去头/时间戳后空正文仍通过 |
| `This is a video.` | A_narrative | 无模板不等于有动作内容 |
| 中文动作句 | A_narrative | 英文词规则不适用时仍输出 A；中文并非差标签，但不能据此判英语叙事质量 |
| `One side wrist moves left. The other side wrist moves right.` | C_raw_template，tmpl=1 | 正则只识别部分固定开头 |
| `One wrist moves left. The other wrist moves right.` | A_narrative，tmpl=0 | 近乎同义的词形变更即可跨越等级 |
| 100词中5个动作词命中 | narr=5 | 宣称每千词密度的公式应得到50 |

具体代码：模板正则位于第8–9行；`narr / max(len(words) / 1000, 1)` 位于第42行，短于1,000词时实际返回命中次数；分层决策位于第57–66行，没有动作有效性和事实核验。

上游文档的 A/B/C 条件描述也不等同于代码。例如 C 的第一条实际要求 `tmpl >= 0.75 AND dup >= 0.35`，另有 `tmpl >= 0.9`；并非所有模板率超过75%都进 C。因此暂不据其层名决定训练准入，也不把修正公式后的新分布覆盖成旧统计。

报告另有三处需要收紧：

- “6,019条可直接训练/评测”只能改成“待审候选”；评测参考尤其不能由文本规则直接认证。
- “C层窗口与事件覆盖准确”超出了现有证据。ID、窗口数、边界相等只验证结构，不验证视频事实与语义覆盖。
- “不是模型能力问题”尚未由少量好例子证明；提示、源表示、视觉采样、模型能力与输出预算均可能影响结果。

这不是要求删除关节词或强制开放词汇。需要修的是不必要的表达冗余、时序含糊和事实错误；重复舞步、常用部位及方向表达应保留。

## 4. 生产过程尚不能完整复现

新增报告引用 `m2d/annotate_pipeline.py`、`batch_annotate.py`、`retry_fill.py`、`final_merge.py` 等生产入口，但这些文件未在该 main Git 树中找到。报告自述还包含纯文本兜底和 sample_id mismatch 降为告警等路径。本轮无法核验它们如何影响实际最终标签，不能把全部记录都认定为同一视觉修订流程。

应回收实际执行源码、system/user提示、模型与processor版本、视频解码/采样设置、原请求和响应、重试及兜底路径、合并去重规则。逐记录标记真实输入模态；只有视频路径存在不代表请求实际携带并使用了视频。

模型自报的 evidence_frame_ids 需要与实际送入的帧及时间绑定。若服务内部帧采样未导出，先保留“帧证据未独立核验”，不把 coverage 引用或帧号字符串当成视觉真值。

| 实验线 | 已知信息 | 当前缺口 |
|---|---|---|
| main 历史 full-v4 | 训练记录自述来自 qwen35_captions；196,097训练样本、6,129步 | 原输入文件与实际目标的逐行身份 |

main 的 [TRAINING_RECORD](https://github.com/Anachronism-N/H3-posttrain/blob/ce4fc961fea11394b12646821a370186b3e7983b/scripts_omnidance/exp/ms/planner/docs/TRAINING_RECORD.md)与当前benchmark训练不是同一运行。其 [build_full_v4.py](https://github.com/Anachronism-N/H3-posttrain/blob/ce4fc961fea11394b12646821a370186b3e7983b/scripts_omnidance/exp/ms/planner/data/build_full_v4.py)接受任意 `--merged` 的 motion_caption，并统一写成 `m2d-full-v4`，该版本名本身不能证明输入身份。旧 `rich_ms_fusion_source_assumed_text_cleanup_v1` 也是另一套导出的来源声明，不能仅凭仓库同时存在就断定当前训练用了它。

零新前向即可回收并关联：实际run config、训练/验证文件SHA、caption contract、转换代码SHA、HF固定revision；逐记录对照 `id / source_group / split / audio_sha / raw_caption_sha / target_text_sha / windows`。先计算已核实匹配、变换后匹配、不匹配和未知的数量，再讨论当前模型是否暴露于该批模板目标。

即使同源成立，也只是增强了“目标表达可能影响自由生成”的假设。数据层相关性不能排除结束监督、推理合同、采样轨迹或音乐条件利用等因素。修订后的标签更好，也不能直接推断训练循环会消失。

## 6. 标签改善应该怎样做

保留一个可追踪的事实层，再产生适合编舞阅读的表达层：

1. 事实层保存源事件ID、窗口、部位、侧别、坐标系/朝向、方向、时序/同时性和不确定性；疑似错误允许以视频证据纠正，而不是强迫正文忠实于错误源事件。
2. 将能明确同向连续或同时发生的事件组成组，允许一句话对应多个源事件，也允许一个源事件分布在多个短语；coverage是多对多映射，不要求一事件一句。
3. 表达层描述身体动作与过渡，不奖励服饰、道具、舞种名称或同义词数量。动作粒度以编排可用性为准，不扩展到细手指控制。
4. 用后验核验检查方向/侧别/先后、真实反转、重复和重要遗漏；新增内容必须有实际视频支持。

**连续三条同向 posecode 不等于动作重复三次。** 它可能是同一次持续运动的多个观测。写 `repeats N times` 前必须识别真实周期并核验视频；同样不能把三个真正重复舞步压成一次动作。保真审查不能被模板率、8-gram或某个字数阈值替代。

## 7. 下一轮有界实验

### L0 标签审计与训练谱系，先做且无需模型

审计原始train和val/test文件：来源、重复ID、split冲突、空正文、正文与窗口文本诊断及标签版本。保留原件；先不筛掉所有C层，不把A/B层塞进隐藏测试集。来源ID存在不证明歌曲/近重复隔离，后续仍需音频与视频组件核对。

本轮新增的CPU工具见第8节。目标是获得可信分母和下一步抽样依据，不是输出“可训练=true”。同时完成第5节的训练来源链；新工具本身不替代逐ID目标转换对照。

### L1 标签表达与视觉增量，最多180次生成，无训练

从已核实来源组件中预先抽60片段：40个随机来源＋20个压力来源，后者覆盖高重复、复杂时间组织、遮挡和低模板但疑似无效内容。每组件最多一片段；均与正式benchmark隐藏测试分离。压力样本独立报告，不能用其平均质量估全量数据比例。

| 实验臂 | 输入与规则 | 作用 |
|---|---|---|
| R0 | 原生产提示＋原MotionScript＋原视频，重新生成 | 与R1匹配模型、视频输入和预算，形成提示对照 |
| R1 | 事件组保真表达＋原MotionScript＋原视频 | 检验是否改善组织且不损失事实 |
| R2 | 与R1同表达/保真规则＋原MotionScript，移除视频；缺证据时不允许视觉补充 | 与R1比较可核验的视觉增量 |

三臂同模型版本、解码、窗口和输出预算；R2的无视频状态显式标记，不能伪造视觉证据。历史原输出只作零新增调用参照。R0的原生产代码/提示缺失时，先追回；否则改名为重建baseline，不能声称严格复现。

上限 `60 × 3 = 180` 次生成，失败保留、不补抽，模型judge调用另计。先运行预登记的12例共36次检查接口；若提示与合同不变，可继续剩余48例144次。若改提示，先前12例成为开发记录，另建版本；本预算内最终版本仅48例，不能合称60例，补齐60例最终版本将达到216次总调用。所有提示冻结后才进入留出质量验证。

开发期助手可读文本先筛查；视频事实、音乐适配和模糊动作需要实际有相应输入的评价。人工先聚焦12例；正式标签优势主张应覆盖预先冻结的来源子集并如实报告范围，模型初审不计为人评。隐藏方法与tier，评价侧别、方向、时序/同时性、次数、遗漏、无依据补充和可读性。语言更短但漏事实、或更丰富但幻觉增加都不算胜出。

只在R1优于R0且事实保真得到支持时扩量；R1若不优于R2，不能宣称视觉润色有增益。是否添加“无MotionScript的视频开放描述”作为第四臂，取决于是否确实要研究闭集源表示的遗漏；它另需60次生成预算，不能混入本次180次。

标签研究不必阻塞harness开发。保留已有候选库、大纲和原计划前缀，先追溯0.75秒动作过载、相同动作串3.5秒→1.25秒、结尾freeze后继续动作等实例，区分候选源、规划器复制和时间压缩。

## 8. 本轮CPU工具与运行方式

新增 `captionlab.label_audit`，只处理本地JSONL，不加载模型、不读取视频、不更新标签或训练清单。它输出扫描身份与文本诊断；扫描完成不代表质量合格。实现、测试和示例见[CaptionLab说明](../captionlab/README.md)。

输入应是互不重复的原交付文件。例如服务器在仓库根目录运行：

```bash
python -m captionlab.label_audit \
  --input /data/qwen35_captions/train_captions.jsonl \
  --input /data/qwen35_captions/valtest_captions.jsonl \
  --out /data/audits/qwen35_labels_v1.json
```

路径为需替换的服务器示例；不能同时加入已含这两份记录的all文件。输出使用新路径，不覆盖历史报告。输入缺字段或坏行保留统计与有界位置示例；聚合不输出完整caption，也不直接产出所谓优质样本ID列表。

资源：L0只需CPU、原文件及谱系回执；L1需要可用的视频语言服务，模型部署按实际既有合同，不为此重建大规模并行标注集群；H1只需文字服务；C1在原件分析时不需GPU，40条新生成才需要已核验推理布局。所有新增模型实验本轮均未执行。
