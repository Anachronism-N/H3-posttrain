# 两条实验线的独立判断与推进：Harness / Qwen Captioner

日期：2026-11-09。基础：`8a833c9`训练复盘、`e91d4c1`诊断代码，以及原v11/v17 harness服务器记录。用户明确要求两部分都判断；不能用Captioner诊断替代harness实验，也不能把harness的软件测试作为Captioner学会编舞的证据。本轮不训练。

## 1. 两条线各自回答什么

| | Harness实验 | Qwen Captioner训练实验 |
|---|---|---|
| 核心问题 | 相同音乐证据/局部动作候选下，大纲、历史、时间分配和编辑是否改善整曲编舞 | 模型能否利用音乐条件生成合理的局部动作文本，且停止、目标协议、舞种分类可靠 |
| 主要比较单位 | 歌曲、指定编辑任务；任务/seed嵌套在歌内 | 独立来源组；局部样本的生成和同目标音频条件对照 |
| 优先固定 | 局部expert、候选bank、音乐证据、计时合同、模型预算 | 数据/split、初始化、曝光预算、目标事实、评估样本及负例策略 |
| 主要质量证据 | 音乐贴合、长程结构、计划可执行性、编辑目标/保持/边界的独立听音评审 | 独立生成合理性与音乐适配；条件似然是诊断，JEV单独验收 |
| 当前判断 | 流程已执行，质量效益未证实；可以继续，不用等重训 | SFT技术链路已跑通，现有报告不支持直接全量放大；先诊断再小预算训练 |
| 是否互相阻塞 | 现有expert/候选可冻结继续评价 | 不需要先跑完整harness才诊断局部模型 |

**合理编舞不等于从音乐唯一还原原视频。** 侧别、具体次数或动作选择可能存在多种合理答案。GT事件匹配主要用于保事实转换、记忆验证、描述一致性或明确用户brief；不能把合理替代编舞直接算作音乐映射失败。反过来，通用动作也不能仅靠语法正确或文本loss低就算音乐适配成功。

## 2. Harness：先取得已有结果的质量证据

### H0：现有结果评价，新增模型调用0

服务器记录已有三首歌、三种规划条件，共9份整曲计划；另外有3个真实编辑版本。3个no-op展示与对应原main相同，不能重复算成3个新生成结果。原始v11/v17工件尚未在本机获得，下述是代码与记录核对，不是本地重算。

| 对照 | 已有结果 | 判断问题 | 解释边界 |
|---|---:|---|---|
| v11 O+H vs O无H | 3歌×2组 | 固定实际同一大纲，历史是否改善发展/衔接或造成复读 | 单次解码，不能据此声称稳定因果效应 |
| v11 O无H vs v17 无O无H | 3歌×2组 | 大纲意图与主题权限整体是否有用 | 同时改变主题权限，且跨session |
| v17 editor vs no-op | 3任务×2展示项 | 降低幅度是否真达成，其他动作/范围/边界是否保持 | 仅第一事件的狭窄替换，不代表任意编辑；先审原计划是否已满足指令，no-op不能预设必败 |

O指大纲及主题权限，H指已提交历史。Main vs independent同时改变O/H，适合评价整套方法，不能把收益全归某一个部件。

立即使用现有v17生成/编辑包收取真实评分与时间证据；若补入O无H条件，构造新匿名包，不改旧计划/绑定。两名评审、三条件九计划、四生成维度是72项维度评分；只先用现成六计划包是48项。编辑六展示项×两人×目标/保持两维是24项，边界再加12项。**独立歌曲仍只有3首，不是72个样本。** 当前提交评分仍为0；来源组没核实，不报告正式CI或赢家。

该阶段的交付是逐歌问题表和配对判断：哪些部分有帮助，哪些机械复读、内容冗余、转折或编辑失败有具体证据，哪些无法判断。先用结果识别主要瓶颈，不再为“做完矩阵”自动新增76次调用。

### H1：按H0问题选择一个实验，不一次改全部模块

| H0观察 | 下一步 | 不应做的归因 |
|---|---|---|
| 历史使动作持续复读，结构没有发展 | 固定同expert/bank/大纲，比较历史摘要/状态表达；先小规模 | 把不同expert生成的候选差异算作历史收益 |
| 大纲过于笼统或限制不必要 | 固定历史和候选，检查大纲是否引用实际音乐转折；预先定义对照 | 用大纲/权限/候选一起变化的结果证明纯prompt收益 |
| 近均分三事件限制音乐时间分配 | 进入下面9块、18次局部timing probe | 用“更接近输入预测拍点”自证更贴合音乐 |
| 编辑只换soft/small等词，实际幅度未降低 | 扩大明确目标/保护事实的编辑任务，逐目标语义裁定 | 将合法patch或字面变动当语义成功 |
| 候选本身大多不合音乐，harness只能重组通用词 | 保留这份受限结果；待局部expert独立改善后进入联动实验 | 直接同时改expert和harness，再把效果全归harness |

时间菜单探针的进入条件是实际听音观察支持时间分配问题。预指定每歌首/中/末各一块，共9块×两组，最多18次文本调用，新增音频/大纲调用0。两组固定原unit端点、事件数、最短时长、候选、音乐证据、大纲、同一原计划前缀、模型、seed、输出cap。一个用原均分排程，一个用预测拍点附近排程；不可行预登记回退并保留分母，局部输出不反馈进其他探针历史。

该探针的独立冻结前缀/外部排程入口尚未实现，需要新合同和目录。74/76块有替代切分只是可行性。先完成人评再决定投入这部分代码，不把它作为必跑模块。

### H2：Bench扩展所需代码，优先于新增自动质量总分

现有一歌一任务评审可立即开展。若扩到一歌多编辑、多seed，下一项CPU代码顺序为：

1. 独立冻结任务库存，身份含dataset/task/source-plan/method/seed；未入包、失败、弃权、待评都保留。当前review聚合以song+method唯一定位，不能直接塞入同歌同方法多任务。
2. 独立语义裁定文件，绑定任务及before/after SHA；逐目标/保持事实记录pass/partial/fail/unknown及证据，和硬保护/边界分开。整体4分不能自动转换成所有目标通过。
3. 明确已审阅时间范围，按区间并集统计观察到的问题；空issues不是已确认零错误，合理主题回归不算病理重复。

正式规模仍建议按既有[benchmark设计](../choreobench/docs/BENCHMARK_METRICS_20261109_zh.md)逐步建立隔离来源、冻结任务、标注协议和指标校准。现有三首是开发证据，不能直接包装成完整benchmark已验证。新数据规模和方法数需先算实际调用与人工预算，不将逐事件评分当独立歌曲扩大显著性。

## 3. Captioner：诊断之后才启动有界训练

### C0：现有模型的技术与条件信息核验

沿[实验35](35_captionlab_experiments_20261109_zh.md)执行E0→E1。原运行日志显示loss下降、greedy病理循环、真/错配差值有限；证据不足以推荐继续193k全量、延长epoch或默认EOS20。也不足以断言模型完全忽略音乐。

先实际恢复标准SFT/EOS20/官方初始化的原native协议，核验完整目标、EOS、张量恢复，再做少量case及固定256验证来源的true/random/hard/silence评分。原三例生成可先审阅已有原件；若不属val，不改split标签。真/错配同y的NLL差只说明该目标的条件似然；负例必须审到确实不兼容，尤其节奏/风格相近的音乐可能共享合法编舞。

新`captionlab`已实现清单/转换/评分内核/汇总和运行桥合同。真实factory与权重、动作信息token映射、KV/ZeRO/portable一致性仍需在原环境验收。未自动产生的action mask保持NA。分类标签可靠性和拒识另算，不把unknown生成问题混成JEV分类问题。

### C1：需要真正接通并验证的新目标训练合同

报告34提出的P0–P3值得做，但**当前新诊断代码不是P0–P3训练器**。启动前要完成：

- 版本化actions-timed/actions-untimed loader，raw与权威时间完整保留；原v2要求舞种header及时间格式，不能直接换文件路径冒充兼容。
- 复用已有JEV能力并验证新合同下只读取原音频prefix，unknown标签mask、按样本独立全局分母、与caption loss的权重关系；不注入真实舞种作为推理时不可得的信息。
- adapter与JEV一起完整export/新进程restore；至少2个真实update、一次恢复，以及单case→8case有界记忆验证。记忆测试可以检查原参考细节，不能替代一般生成评价。
- 固定来源、曝光秒数/事件数、global batch、监控点、参数/优化器范围；先profile真实最长目标和100个预热后更新，再预算耗时。

这些是下一项Captioner代码工作；已有原trainer/JEV可复用，不要求从零另写30B训练框架。本轮不启动训练。

### C2：最小有解释力的训练矩阵

共同2k–5k原来源、rank32、同一JEV协议及权重、相同预算，不加EOS20、不禁正常重复：

| | 音频LoRA末4层 | 音频LoRA末16层 |
|---|---|---|
| 保留时间戳 | P0 | P2 |
| 去数字时间戳 | P1 | P3 |

资源紧张可先P0/P1验证输出负担，再补P2/P3；**两组先跑不等于已经测完交互**。P0已从旧输出合同拆出舞种，不可把P0与旧SFT差异全部归因于JEV；JEV自身收益要有同协议lambda=0对照。0.1是可预注册起点，不是最佳值声明。

主验收同时看：新合同技术正确、合理动作与音乐适配、病理循环/停止、来源隔离；JEV看known覆盖、逐类support、macro指标与拒识。协议变化后的原始NLL不能直接横向排名，无时间戳版本不再用完整秒级覆盖验收。

### C3：由失败原因选择后续，不自动全跑

- 技术正确但小样本记忆不足：先排优化问题，再考虑rank32/64；不能只靠参数少判断容量不足。
- 输出过长且完整短窗可靠：比较1–3秒原窗，先真实裁剪/PCM/pad核验和上下文准入；按来源曝光匹配，不拿切成更多行后的“1 epoch”冒充等预算。
- 生成基本合理但音频辨别弱，且已有已审负例：可试小权重条件ranking，至多一个负音频起步；匹配分提升不能抵消生成退化。可先于盲目扩大rank，但仍不是当前必跑项。

EOS额外加权、全语言解冻、RL/DPO都不是当前证据支持的首要方案。

## 4. 两条线何时联动

第一阶段保持分开：harness使用原冻结bank评结构/编辑；Captioner使用独立验证清单诊断/训练。局部模型有可靠改进、导出协议和人评有效性确认后，再做小规模联动：

| 局部expert | 独立受约束逐块baseline | 固定版本harness |
|---|---|---|
| 原expert | L0-H0 | L0-H1 |
| 新Captioner | L1-H0 | L1-H1 |

每个expert仅生成一次新候选bank，再由该行两种规划方法共享；同一个expert内部不要为某个方法单独重采样候选。两行保持观察窗、候选预算、下游计划schema、模型与评估一致，记录实际差异。新的variable-window/无时间戳协议需新版本provider/导出桥，不能静默映射为已知精确秒级动作边界；也不能resume旧v11冒充同一实验。

这个2×2用于分开expert效应、harness效应及其交互，**不要求现在补跑**。先完成H0与C0，否则增加调用仍无法定位问题。局部NLL改善但整曲无收益，或harness收益只在某个expert成立，都应如实报告。

| 优先级 | Harness线 | Captioner线 |
|---|---|---|
| 立即并行 | 收齐原v11/v17工件和匿名听音评价；新模型调用0 | 接原检查点factory做E0，再冻结256验证probe；无训练 |

H0需要实际评审与原工件，无新增GPU推理。C0优先1×80GB卡顺序加载，原报告约61GiB权重占用不等于峰值保证；CPU内存/磁盘与调用预算见实验35。C1/C2优先复用已验证的8×A800 ZeRO3节点，先小预算，当前不预订也不启动。人工工时、API token、GPU wall time分别报告，不互相换算成未经测量的成本。
