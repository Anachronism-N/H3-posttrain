# ChoreoBench implementation contract (v1)

Python >=3.9. All times are integer sample indices in the canonical song sample rate; half-open intervals. JSON dictionaries are used at module boundaries. Contracts, data preparation, baseline execution and evaluation are separate modules.

Dataset: {schema: "choreobench.dataset.v1", dataset_id, synthetic: bool, grouping: {status: "unverified"|"reviewed", evidence: str}, songs: [...]}.
Song: {song_id, split: train|dev|test, song_group_id, artist_group_id, near_duplicate_group_id, brief: str, audio: {path, sha256, sample_rate: int, num_samples: int}, music: {source: str, beats: [int], downbeats: [int], sections: [{section_id, start: int, end: int, label: str, repeat_group: str|null}]}}.
Group IDs are nonempty strings or null (null precludes release eligibility). Relative audio paths resolve against dataset JSON directory. Sections form a partition; no invented beat positions. Missing music structure may explicitly use one whole-song section labelled unknown. Music fields are public tool predictions, never private reference answers.

Plan: {schema: "choreobench.plan.v1", song_id, sample_rate, num_samples, motifs: [{motif_id, description}], events: [{event_id, start, end, track, action, attributes: {}, entry: {}, exit: {}, motif_id: str|null, evidence: [str]}], provenance: {}}.
Tracks: body, upper, lower, head, torso, left_arm, right_arm, left_leg, right_leg. Action is nonempty open natural language. attributes/entry/exit are scalar-valued JSON objects; unknown represented null. Same-track overlap disallowed; incompatible scope overlap flagged by validator (body overlaps any track; upper overlaps torso/head/arms; lower overlaps legs). Simultaneous distinct tracks allowed. Full coverage is reported, not universally forced by schema. Rest must be explicit action+attribute if intended. Event list canonical order (start,track,event_id); schema validator does not silently reorder. Full-document song/clock/motif references are validated.

schema.py provides validate_song(song), validate_plan(plan, song=None), validate_dataset(dataset), ValidationError(ValueError). Return input on success. io.py provides read_json(path), write_json(path,obj,overwrite=False), object_sha(obj), file_sha(path), atomic_write(path,obj), file_lock(path); strict JSON (no duplicate keys, NaN/Infinity).

Editing API: editing.py apply_patch(plan, patch) -> new validated plan; patch {schema:"choreobench.patch.v1", base_plan_sha256, instruction: str, allowed_event_ids:[id], repair_event_ids:[id], protected:[{event_id,field}], operations:[{event_id,field,value}]}. v1 supports replace existing event fields only: action, attributes.KEY, entry.KEY, exit.KEY, start,end,track,motif_id. No additions/deletions or changing IDs. No-op is preserved and evaluated, not rejected by execution alone. Explicit empty patch can represent abstention; CLI reports it. All operation keys strict; no silently dropping invalid ops. Protected fields support whole field (e.g. attributes) or dotted scalar path, also event_id "*" to protect field across all events if useful. No arbitrary code execution. provenance updated only with patch binding. All external song/clock/motif fields immutable. Unknown/ambiguous natural-language targets handled by API planner or manual contract, not a brittle regex parser.

Evaluation API: evaluation.py evaluate_plan(plan,song) -> JSON diagnostics; evaluate_edit(before,after,task) -> JSON. Task {schema:"choreobench.edit_task.v1", task_id,song_id,source_plan_sha256,instruction,allowed_event_ids,repair_event_ids,protected,goals:[{event_id,field,op:"eq"|"contains"|"gte"|"lte",value}], semantic_goals:[str]}. Goals kept private: only instruction, allowed/repair IDs, protected fields, source plan reach model. Structural goal checks labelled literal checks, not semantic truth; semantic_goals remain pending independent review. Core report cannot assign musicality/physical scores automatically. export/import blind reviews and song-level bootstrap are exposed in evaluation.py and reviews.py.

Baseline API: audio.py/providers.py/baseline.py. Expose run_baseline(dataset_path, output_dir, config, resume=False) -> result metadata. Config JSON includes mode concat|global|hierarchical, local_provider {kind:mock|native|replay,...}, planner_provider {kind:mock|chat_completions,...}, seed:int, max_calls:int, max_output_tokens:int, window_seconds:5.0625, stride_seconds:<=window, candidates_per_window:int. Real providers lazy load, preserve raw results and exact identities; no mock fallback. Existing native sample_native adapter strictly audio-only. An optional local_provider.task_prompt supports a separate prompted Omni base-only baseline: bounded plain fixed public task text, no checkpoint, no per-song context or private answers. It overrides only that ChoreoBench adapter instance, leaves original training prefixes unchanged, binds prompt/source hashes and preserves the formatted template. Identity protocol is choreobench-prompted-omni-base-v1; strict fixed-window parsing remains mandatory. Use full 5.0625s windows, shift final window left, no silent padding of too-short songs. Output ownership intervals separate from observation windows so tail overlap has no duplicate schedule; normalize windows without claiming true action boundaries. Plan schema validated before publishing. API endpoint errors and malformed model output are failures, saved and not retried to hide bad samples. Run journal has immutable contract and per-call started/raw records; completed cached calls reused; pending outcomes block unless explicit retry policy. Store full prompts/responses and costs without API secrets; source/config/checkpoint identity changes prevent resume. Output root contains contract.json, results.json, plans/<song_id>.json, calls/*; completed JSON should store enough identity to verify on resume. The CLI wraps run_baseline. Provide provider classes/helpers for the edit runner using the same API provider.

Integrated CLI: see README and python -m choreobench --help. Includes demo, doctor, validate-data, run, validate-plan, apply-edit, undo-edit, propose-edit, evaluate-plan, evaluate-edit, review-pack, review-import, export-submission, evaluate-submission, bootstrap, resources, prepare-audio, assemble-data, import-structure. Demo is synthetic smoke only; never counted as scientific results.

Implementation clarifications: song IDs must also be portable Windows/Linux filenames and case-insensitively unique; event IDs can contain colons. Baseline config additionally supports splits, continue_on_model_error (default false), and planner_max_output_tokens (default max_output_tokens). Completed queue is distinct from all_songs_succeeded. Plans use hash filenames, mapped in results.json. apply_task_patch() enforces a frozen external edit task; apply_patch() alone only validates its own supplied scope. Actual public/private review schemas and strict replay identity requirements are defined in code and documented in README. No automatic model-training or recursive harness-optimization loop is implemented.

Candidate reuse: candidates.py exports export_candidates(run_dir,out), load_candidates(path), inspect_candidates(path), match_candidates(bank,dataset_sha,songs,inputs,config). Config local_candidates_path selects immutable stored local evidence, not a new local provider. Exact dataset bytes, source audio, selected-song order and local sampling/model configuration match; only derived audio.path may differ across runs. Native weights are not opened on reuse. max_calls/calls_used/new_calls_used concern current-run model calls; local_calls_reused and original_collection_calls/costs remain separate. Known local model failures are replayed, not filtered. Context: context.py build_boundary_context(plan,boundary) provides per-body-part latest declared exits and bounded motif examples, bound to prefix/song/clock; it never infers pose persistence or physical truth.

Targeting: targeting.py resolve_targets(plan,song,selector,strict=True) resolves exactly one selector: {section_id}, {section_label,occurrence}, or {start,end}; optional track (exact) or body_scope (hierarchical), mutually exclusive. strict=False produces a conflict preview only; build_edit_task(plan,song,selector,task_id=...,instruction=...,repair_event_ids=...,protected=...,goals=...,semantic_goals=...) always resolves strictly. No automatic event splitting, scope broadening or natural-language target grounding. CLI preview-target/target-edit exposes this workflow.

Comparison: comparison.py compare_methods(rows,method_a,method_b,metric="value",n_resamples=2000,confidence=.95,seed=0,allow_incomplete=False,value_bounds=None) averages within song/method, computes B-minus-A, and resamples entire source groups. Rows require song_id/group_id/method_id/metric, optional reviewer_id/origin. Default requires complete pairs in the input song universe; explicit intersection reports omissions. Named duplicate reviewers, mixed human/model_judge origins and mixed declared/unknown origins are rejected. Single independent group yields no CI; positive is not automatically better. CLI compare exposes the default unbounded numeric scale.

Blind review accepts independent submissions through review-pack --submission in addition to --run. Optional source_binding on review input items is {kind:"submission"|"run",sha256,dataset_sha256,synthetic:bool}; it remains private, with content binding and imported status synthetic/unknown/declared_real_not_audited. Unknown or declared-real source status does not certify scientific release eligibility. Public review pack format and criteria are unchanged.

Inference harness: planning_units.py build_planning_units(song,windows=None,config=None) -> source-bound disjoint units; validate_planning_units recomputes exact fields. Config bars_per_block=4/max_unit_seconds=20/fallback_seconds=10.125/meter_status=unverified; reviewed is an author declaration, not confidence. Time fallback is default; no semantic phrase detection. selection.py candidate_options(bank,song,units=None), make_selection(bank,song,choices,selection_provenance=None), validate_selection(document,bank,song), select_with_scores(options,unary,transitions,score_provenance=...) preserve whole-response closure. NoFeasibleSelectionError marks explicit abstention under valid scores. compile_selected.py compile_selection(...,timing_policy=strict|proposed_crop) -> {plan|null,report}; strict omits partial captions and reports gaps, proposed_crop remains semantically pending.

harness.py run_harness(dataset_path,candidates_path,output_dir,config,resume=False) supports index0/llm/scores over an existing matching bank, exact original stride, per-window authoritative unit by ownership midpoint, input character/output token/call limits, immutable journal, failure denominators and uniform submission/review export. Synthetic source/selector/score taint propagates. Prior model context includes only retained scheduled fragments. No optimizer, weight update, new local sampling or automatic semantic repair loop. API modes require real model/service acceptance; CPU fixtures only verify contracts.

Resident native expert: resident.py create_resident_server(provider_spec,audio_root,host="127.0.0.1",port=0,api_key_env="") and serve_resident use one NativeProvider, serial generation and lazy weight loading; GET /health and POST /v1/local-caption only. NativeServiceProvider is selected by kind=native_service; requires expected_identity_sha256, supports timeout_seconds/api_key_env/base_url. Current transport requires matching absolute shared-file paths; no uploads, batching or sharding. Identity is pinned server attestation, not independent remote-weight verification; unknown outcomes are never retried. Failed post-load verification locks service until restart. CLI run-harness/plan-units/serve-local and examples are documented in README.


## Public structure sidecar

Schema: {schema:"choreobench.public_structure.v1",dataset_sha256,songs:[{song_id,audio_sha256,sample_rate,num_samples,music,synthetic:bool}]}.

- Exact keys; selected songs exactly match original source dataset. Canonical audio hash/rate/count must match.
- Private goals, audits, references and scoring fields are rejected, not forwarded to a generator.
- Candidate-bank matching still validates original dataset bytes and Song snapshots; the sidecar creates a separate effective public music view only for planning.
- public_structure_path is optional for index0/llm/scores/coordinated. Sidecar snapshot/hash is persisted in the run contract; mutations invalidate resume. Synthetic source/sidecar/provider taint propagates.
- music_structure.py builds sidecars from canonical WAV and versioned, audio-SHA/clock-bound detections (see revision below). Actual detector identity is preserved; spectral-novelty boundaries have unknown functional labels, null repeat groups, unreviewed meter and no calibrated accuracy/phrase claim. Raw novelty, source/config/code hashes remain separate analysis evidence.

## Coordinated harness

Config extends run-harness with mode=coordinated, planner_provider, outline_max_output_tokens, max_events_per_unit and structured_unit_output; selector_provider/scores_path are not accepted for this mode. Defaults: outline budget4096, max_events_per_unit3 (integer1–8), structured_unit_output=false. The example opts in to structured decoding explicitly.

Global outline: {motifs:[{motif_id,description}],sections:[{section_id,intent,motif_ids}]}.

Unit response: {unit_id,events:[{start,end,track,action,motif_id,source_call_ids}]}.

- Every public section exactly once in original order; <=8 declared motifs and section-local motif references.
- Each unit has1–max_events_per_unit events, integer global times wholly inside the public planning unit, valid compatible tracks and original response ordering.
- Every event cites one or more actual local call_ids presented for that unit; unavailable/duplicate references fail. A citation is input inspiration, not semantic entailment, measured physical state or verbatim compilation.
- Controller assigns deterministic event IDs. attributes/entry/exit remain unknown empty objects, not inferred support feet or facing states.
- Whole-song section intent, current permitted motif definitions, per-body-part latest committed text, bounded motif history and recent events guide each block. Validated commits alone enter future history.
- New actions/timings are explicitly new proposals; input-local two-caption observation format is unchanged. No post-hoc text repair, event deletion, forced rest, invisible retry or weight update.
- Budget preflight covers1 outline plus every planned block. Character limits are not tokenizer/context limits; raw responses, stop reasons, costs, failures and immutable resume identities persist.
- Artifacts: contract/calls/units/options/outlines/blocks/diagnostics/plans/results. coordination_contract.v1 and coordination_result.v1 retain the original candidate/audio/public structure bindings. Generic export-submission/review-pack accepts valid final plans; a valid prefix is not a successful whole-song prediction.

### Structured unit decoding

structured_unit_output=true adds an exact public per-unit response_schema to the journaled request. ChatCompletionsProvider sends response_format.json_schema (strict closed object) instead of json_object. Schema binds unit ID, field types, allowed current motifs/source IDs, integer bounds and events.maxItems.

Controller relational checks still enforce start<end, schedule order, incompatible body overlap, motif scope and duplicate citations. uniqueItems is not sent to the verified backend because it is unsupported there; uniqueness is still mandatory in _read_unit. Unsupported schema/service responses fail with evidence, no automatic downgrade or retry. This is not a music/physical evaluator.

### Process/source drift

run_harness and run_coordinated refuse new runs if their own source inode/mtime/ctime differs from its import-time identity, before loading run data/provider. This guards waiting processes that retain earlier configuration code; it is not a full deployment attestation. New revisions require frozen code and a new output directory, not missing-config compatibility fallbacks.

## Planning unit time-fallback revision

Algorithm section_downbeat_partition.v2 adds min_time_block_seconds(default2). Effective tail target is clamped to >=1 sample and <=half the effective fallback size.

- Short time-fallback tails merge with the previous block in the same source section if max_unit_seconds permits; otherwise the last pair is balanced.
- Short source sections remain explicit; reviewed pickup/bar fragments are not silently merged across scope.
- Original integer full-song coverage, public section bounds and audio observation windows remain unchanged. Reasons and algorithm revision are recorded and recomputed by validation.
- This is an engineering unit target, not a minimum generated-action duration or true phrase detector.

## Public review HTTP service

review_server.create_review_server(public_dir,host="127.0.0.1",port=0,proxy_prefix="") serves only a fixed public-route allowlist and pack-bound canonical audio. Valid proxy prefixes are /proxy/PORT. GET/HEAD and audio byte ranges are supported; private paths, directories, unlisted files, traversal, symlink escape and POST writes are refused.

Startup hashes audio and snapshots public documents. Each audio GET/HEAD/Range reads at most startup_size+1 bytes, checks metadata and actual full SHA, closes the source, then serves the same immutable bytes; metadata alone never certifies content. Per-request memory is O(audio file size). No server-side review-write endpoint is added; ratings are filled/exported in the browser and imported with the existing evaluator. The server does not invent ratings, prove that audio was heard, generate HTML or publish private bindings. Deployment-specific UI/assets remain in the operator's public experiment package, not this repository.

## Beat detection source contract

music_structure.py accepts JSONL records with exact required fields {schema:"choreobench.beat_detections.v1",id,status:"ok",audio_sha256,sample_rate,num_samples,time_unit:"seconds",synthetic:bool,detector:{name,version,model_sha256,code_sha256,parameters:object},beats,downbeats}. Optional source_binding={artifact_sha256,record_sha256,run_receipt_sha256:null|sha256}. Times are finite seconds, strictly increasing, non-colliding on the canonical sample clock; raw downbeats must be a subset of raw beats. Exact dataset song inventory, audio SHA and clock are mandatory. Unknown/duplicate fields and nonfinite/duplicate-key JSON are rejected.

Non-synthetic detector model_sha256 and all detector code_sha256 values require lowercase SHA256; synthetic fixtures may use null model_sha256. Detector labels are bounded portable labels; actual name/version/identity form the source rather than an assumed BeatThis label. Output synthetic=dataset.synthetic OR detection.synthetic; audit evidence records both inputs, source binding and identity status declared_not_independently_authenticated.

wrap_legacy_detections(dataset_path,detections_path,output,detector=...,synthetic=...,time_unit="seconds",run_receipt_path=None) writes a new exclusive JSONL without model inference or source mutation. CLI --wrap-legacy requires --detector-identity/--synthetic true|false/--legacy-time-unit seconds, with optional --run-receipt. Original file/record hashes persist; a receipt must bind the source output hash, and existing explicit source claims cannot be contradicted. It is an operator declaration, not automatic authentication or permission to relabel fixtures as real.

analyze_structure(...,splits=None) defaults to all songs; repeated CLI --split accepts train/dev/test to output the exact selected subset. Detection inventory/identity validation still covers the complete original dataset, whose SHA remains unchanged. Empty/duplicate/unknown or unmatched split selections fail. The wrapper never filters by split. Sidecar inventory must match the consuming harness splits.

## Proposed event clock and literal source comparison

Coordinated-only config: event_time_format=global_samples(default)|boundary_ids, event_grid_seconds=0.25, min_event_seconds=0, event_schedule_policy=free(default)|balanced_full_unit. The balanced policy requires boundary_ids. All positive/nonnegative values must be finite numbers (not booleans). The explicit grid example uses boundary_ids and min_event_seconds=0.5 as uncalibrated development parameters.

timing.event_clock(unit,sample_rate,config) creates a public event_clock.v1. Grid steps round nearest sample with half upward, include exact unit.end without padding, and cap at4097 boundaries. Minimum duration rounds upward, with >=1 sample even for min_event_seconds=0. Boundary output is {unit_id,events:[{start_boundary,end_boundary,track,action,motif_id,source_call_ids}]}; indices are integers into the public boundary_samples. Global-sample output retains start/end. Controller compiles then checks duration, order, scopes, sources and unit bounds; JSONschema cannot replace relational checks. A whole unit shorter than the declared minimum marks the song failed before any outline/unit generation; invalid density fails configuration before provider initialization. No stretching, cropping, forced rest or hidden retry.

With boundary_ids and structured_unit_output=true, each event decoder uses complete anyOf object branches: a single permitted start_boundary and end_boundary bounds satisfying the minimum in actual samples. Every branch retains types, allowed IDs, exact keys and time-first field order. There are no sibling constraints outside anyOf that a backend could ignore; the irregular terminal interval is checked using boundary_samples, not an assumed number of ticks. Backend acceptance alone is not proof of constraint enforcement; controller relational checks remain mandatory. Boundary IDs restart at zero in every unit; committed history times are global samples, not local indices.

balanced_full_unit adds public permitted_schedules: one deterministic near-equal contiguous schedule for each feasible phrase count up to max_events_per_unit, always including a one-phrase full-unit option. The model chooses one whole interval array and writes its movement phrases; it does not return a schedule ID or receive private coverage scores. Structured decoding uses complete array alternatives with fixed-time prefixItems and exact lengths. _read_unit also requires the returned interval array to match a permitted schedule. Coverage is a declared engineering design constraint, not a quality result; sequential slots restrict temporal freedom and do not model simultaneous tracks. No previously emitted action is stretched or gap filled. New config/code requires a new output directory.

Requests journal the public clock and optional dynamic decoder schema; contracts hash config/source/units. Stored final plans keep their existing integer global sample schema. Non-coordinated modes reject explicit event-clock options instead of silently ignoring them. Changes require a new output directory.

This minimum applies to coordinated generation, not automatically to legacy plans or later edit patches. Edited timing still requires independent checks.

The unconditional diagnostic new_actions_not_verbatim is removed. literal_source_copies={event_count,exact_match_count,exact_match_fraction,matching_event_ids,comparison,semantic_novelty_verified:false} compares exact Unicode action strings against cited raw responses or parsed fragments only. A match or mismatch is not semantic novelty, motion quality, or musical alignment.
